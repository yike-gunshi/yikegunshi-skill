# 示范：把一篇写好的 Markdown 排成公众号文章

给 wechat-publisher 一篇写好的 Markdown 文章，得到公众号排版后的正文预览和两版推广文案。这是一次真实运行的记录，日期 2026-10-22。

这次只在本地出排版预览：没有推进公众号草稿箱，也没有上传图床。

## 给了什么

一篇写好的长文：[input/普通人该用哪个AI助手.md](input/普通人该用哪个AI助手.md)。

它是同仓库另一个示范例子 [deep-survey：普通人日常该用哪个 AI 助手](../../../deep-survey/examples/which-ai-assistant/README.md) 产出的调研报告，这里放的是原文副本，没有改动。文章的特点：表格多，正文里每个关键说法后面跟着一个指向原文的来源编号，文末是编号来源列表，没有配图。

## 用户会怎么说这句话

拿着一篇写好的 Markdown，说想发公众号就行，例如：

```text
这篇调研报告想发公众号，帮我排个版：input/普通人该用哪个AI助手.md
```

也可以点名调用：

```text
/wechat input/普通人该用哪个AI助手.md
```

## 代确认了哪些门禁

Skill 有几处要用户拍板。这次是演示，由 AI 扮演用户，一律取 Skill 写明的默认做法。

- **确认发布版**：校对发现的问题（见下一节）按校对意见只改格式、不改措辞，改完的发布版直接进入排版。演示时由 AI 按默认确认。
- **选主题**：第一个用 Skill 的默认主题「落日晚霞」；第二个按 Skill 自定义主题表的顺序取下一个「墨竹清韵」。演示时由 AI 按默认确认。
- **图片宽度与封面**：文章没有图片，不需要调宽度；推草稿箱才需要封面，这次不推，没有准备封面。演示时由 AI 按默认确认。
- **推广文案附不附仓库链接**：Skill 规定介绍开源项目时才附。这篇文章不是介绍开源项目，所以不附。演示时由 AI 按默认确认。
- **发布时间**：按 Skill 的规则给出建议时段和分批投放安排，写在推广文案末尾，没有真的发布。演示时由 AI 按默认确认。

## 校对发现了什么

Skill 的校对一步要通读发布版，查错别字、语病和格式。这篇文章没有发现需要改的错别字和语病，但用 Skill 的排版引擎先渲染一遍，暴露出几处会让公众号正文变形的格式问题，都在发布版里修好了：

- **美元价格被当成数学公式**：排版引擎默认会解析数学公式，两个美元符号之间的文字被排成了斜体公式，价格里的美元符号消失、空格丢失。发布版把美元符号转义成普通字符。
- **来源编号是外链**：公众号正文不能放外链。排版引擎会把每个链接改成脚注，另编一套号，和文末来源列表的编号对不上；「落日晚霞」主题又把脚注整段隐藏，正文里只剩一个孤零零的数字。发布版把正文里带链接的来源编号改成纯文字的「[编号]」，对应文末「口径与来源」的编号列表；「推荐阅读」里的链接标题也改成纯文字，网址都留在文末列表里。
- **网址和邮箱被自动识别成链接**：文末来源列表里的网址会被自动变成链接，网址后面紧跟的全角括号日期会被一起吞进链接，文末还会多出一节重复的「引用链接」。正文里的一个客服邮箱也一样。发布版用代码格式包住这些网址和邮箱，原样显示、可以复制。
- **保留未改的**：文中「确认单」是调研流程里的说法，公众号读者可能看不懂；标题区那行「确认单由 AI 按课题默认填写」也属于调研说明。这些是措辞，按默认不动原文。

## 本地预览是怎么出的

Skill 自带的发布脚本把渲染和推送绑在一起：一启动就要求公众号凭据，渲染完立刻推进草稿箱，没有只预览的选项。所以这次没有运行它，做法是：

1. 用发布脚本背后的同一个排版引擎，注册 Skill 自带的同一套主题样式文件，用和发布脚本相同的渲染参数，只取渲染出的正文 HTML。
2. 把正文包进一个手机宽度的白色页面，存成本地文件。全程不读取任何凭据，不调用任何微信接口。

预览外框额外做了两件事，都和排版主题无关：长网址自动折行，和公众号正文的显示习惯一致；超宽表格在框内左右滑动。「落日晚霞」的设计说明写的是表格左右滑动，但排版引擎没有生成滑动容器，所以预览里补上了。真推到公众号后表格怎么显示，要以公众号后台的预览为准。

## 和 Skill 默认做法不同的地方

- **图片一步**：文章没有图片，图片压缩上传脚本没有可处理的内容，也就没有运行。它在没有图片时不生成图片地址对照文件，而生成发布版的脚本要求有这个文件，所以这次给了一个空的对照文件。
- **发布版的格式修正**：Skill 的流程是校对后报告问题、由用户确认后手动修。这次问题较多，用一段一次性脚本按上面的规则统一改。

## 因为是示范而没做的步骤

- **上传图床**：图片压缩后上传阿里云 OSS 这一步没做（文章本来也没有图片）。
- **推进公众号草稿箱**：没有运行发布脚本，没有调用任何微信接口。真要推的话还得先准备一张封面图：正文里没有图片可以顶替，没有封面就推不进草稿箱。
- **按建议时间发布**：发布时间与投放建议照常写了，但没有真的发布。
- **提交归档到内容库**：Skill 收尾会把文章目录提交到内容库，这次跳过。
