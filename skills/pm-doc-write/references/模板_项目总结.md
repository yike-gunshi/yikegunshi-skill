# 场景模板：项目总结

适用：项目复盘与方法论沉淀的教学型长文，把一个项目踩过的坑提炼成可复用的方法，写给团队学习。思考、工作整理类文档没有专属范文，以本模板为就近模板裁剪使用：保留原则先行加案例佐证的骨架，裁掉附录案例和草稿区。

## 固定骨架（顺序锁死）

1. 开头 callout：一句话说清本文内容（以什么项目为例、介绍什么方法）
2. `# 一、概念介绍`：核心概念用设问引出（SFT 是什么？），行业常见做法用概念对比表格分层铺开
3. `# 二、方法论`：按业务类型分类给出理想做法，每类都落到标准、样本、指标三要素
4. `# 三、项目实践踩过的坑`：因果叙事，先一段话总述踩了什么坑加导致的后果，再一段话归因，配踩坑做法与理想做法的对比表格
5. `# 四、更理想的做法`：主题分区（如理想态定义、样本构造），区内 H3 小节复用统一的三段式模板（见下）
6. `# 附录：更多案例`：badcase、goodcase、迭代过程明细表全部收在这里，正文只留结论
7. `# 草稿`：文末保留草稿区，存放未整理完的表格和画板，不删除

## 小节（H3）写法：原则加项目经验三段式

- 首条是原则：加粗引导词开头（原则：），一两句话说清这一环节的判断标准，先于任何案例出现
- 第二条是项目经验，内部按 做法 / 问题 / 优化 三段编号展开；多轮迭代写成 问题1 / 优化1 / 问题2 / 优化2，不合并
- 优化里的效果数字带基线（badcase 率 10%→3%），不写孤立数字
- 每个小节文字之后紧跟证据表格：实验迭代用多列表（实验版本、实验链接、训练数据、问题与核心变化点、指标、实验表现）；标准或评测集的前后对比用两列表格，单元格内嵌截图分栏
- 延伸经验、口径注释、参考文档放 blockquote，与主线区隔
- 涉及 Prompt 的地方用代码块贴完整原文，不摘要
- 概念对比一律用表格（类型、核心目标、典型场景），不写并列长段落

## 语气要点

- 完整句叙事：本场景是通用约束压缩句式规则的例外，教学与方法论类文档用完整句成段讲清因果，不用名词短语加冒号的简报体
- 教学书面体和大白话类比混用：抽象概念后面紧跟一个生活类比（SFT 就像培养一个能力强但没经验的职场新人），类比放 blockquote，可带 emoji
- 多用设问推进：SFT 是什么？标准该怎么定？先抛问题再回答
- 金句加粗，一节最多一句：标准错了，模型越稳定，线上错得越稳定
- 踩坑写成因果链：踩了什么坑、为什么踩、怎么回捞，敢于写自己的原因（缺少经验、缺少思考的主动性），不粉饰

## 精选片段（学结构和语气，别照搬内容；业务名称与数字均为虚构示例）

开头定调加设问加类比的形态：

> （callout）本文内容：以搜索业务 main agent 的 query 改写任务为例，介绍 SFT 的核心环节和经验沉淀
>
> **SFT 是什么？**
>
> SFT 的本质，是用一批标准输入到结果输出的样本，告诉模型遇到这种情况标准答案就是这样，让它以后照着这个标准稳定输出。标准很重要，**标准错了，模型越稳定，线上错得越稳定**
>
> 举个例子：SFT 就像培养一个能力强、但没经验的职场新人，需要给他一份标准作业手册，让他知道工作中出现情况 A 需要采取动作 B，形成稳定处理方式

原则加做法 / 问题 / 优化三段式的形态（1.3 评测集小节）：

> 1. **原则：**评测集是牵引模型迭代的标尺，需要根据业务场景、具体项目进行设计。一般会包含随机评测集、专项问题评测集等，用来衡量整体效果、以及对特定 badcase 的解决情况
> 2. **query 改写项目经验：**
>    1. **做法：**针对 query 改写生效场景，设计了搜索经验决策随机评测集 500q、IM 渠道随机评测集 100q
>    2. **问题：**评测集构建缺少问题牵引视角，IM 渠道的评测集只有随机单轮 query，无法牵引线上体验较差的多轮 query 记忆丢失问题优化
>    3. **优化：**补充 100 个 IM 多轮随机 session 作为评测集牵引优化多轮记忆丢失问题，最终 badcase 率从 10%→3%

踩坑因果叙事的形态：

> 1. **踩了什么坑：**query 改写在 SFT 阶段主要踩了两个坑。一是理想态定义阶段，标准未结合用户后验、指标缺乏端到端视角、评测集缺少问题牵引；二是样本构造阶段，样本种类缺少、样本配比失衡、样本质量存在瑕疵。以上两个坑导致实验指标劣化（实验链接），经过几版迭代后才完成回捞
> 2. **踩坑的原因：**主要有两点。一是缺少经验，思维惯性基本都是先验制定标准，过往经验中缺少用后验数据定标准；二是缺少思考的主动性，赶节奏的项目容易上来就陷入执行，没有前置做样本设计的思考，变成遇到一个问题、补一类样本

概念对比表格的形态：

|  | query 改写 | 工具调用 |
|---|---|---|
| Teacher 批量标注 | 筛选线上换 q 数据作为打标结果，两个大模型进行 judge | 三个大模型直接打标 |
| 人工 review | 模型均认为改写合理的样本，人工 review | 模型投票不一致的样本，人工 review |
