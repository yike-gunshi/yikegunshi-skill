# 场景模板：周报

适用：每周业务周会的进展汇总文档，多模块、多负责人、面向老板和协作方。单人单方向的轻量周报也可裁剪使用（去掉模块分区，保留 Todo 闭环加进展加数据三段）。

## 文档组织

- 多周堆叠在同一篇文档：新的一周写成新的 H1（日期加周报，如 0804 周报）置顶，旧周下沉，周与周之间用分割线
- 文档最顶部维护一个跨周不动的区块：会议元信息（引用块）加阶段性里程碑（callout），每周只更新里程碑状态，不重写

## 单周固定骨架（顺序锁死）

1. `## Todo`：两列表格，左列上周会议留下的 todo（编号加 @人），右列结论或进展。这是闭环区，上周每条 todo 必须有着落；结论长的写一行并跳转锚点到下方对应模块
2. `## 用户反馈`：VOC 数据一行（新增反馈数、核心诉求、监控链接），洞察一到两条 bullet，细节跳转对应模块
3. `## 核心数据`：实验元信息放引用块（实验链接、分组、流量、时间），核心指标用加粗场景名开头的压缩段落（场景名加逐个指标数据），后接明细表格；埋点异常等口径问题当场标注
4. `## 一、二、三…` 中文序号一级分区，按业务模块划分（如产品框架、能力建设、评测、体验调优、性能调优）。分区下每个子模块一个 H3

## 子模块（H3）写法

- 标题：模块名，尾部挂 @负责人（一个模块可多人）
- 首行：加粗的关键进展引导语，后接 bullet
- 每条 bullet 的形态：结论或状态先行，节奏日期显式（8/4 提测、8/10 合码、8/18 开实验），涉及文档一律链接化不复述
- 嵌套 bullet 展开子项，层级不超过三层
- 老板寄语、口径注释、原则性论述放引用块，与进展区隔
- 已完成或已作废的事项用删除线保留，不删除

## 语气要点

- 简报体：短句、数据密集、大量名词短语加冒号加状态，不追求完整句
- 结论先行，归因紧跟：指标变化一句话，收益或异常来源一句话
- 风险和异常不藏：推测 search 埋点异常上报，排查中，这样的降级表述照写
- 节奏必须落到具体日期，不写近期、尽快
