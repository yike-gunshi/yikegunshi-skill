# 模板：调研报告 / 证据类分析

适用：业界方案调研、论文调研、最佳实践梳理、技术选型论证等以证据为核心的文档。这类文档的验收标准与汇报类不同：读者要能根据细节自行判断结论是否成立，所以证据链完整性优先于篇幅精简。

## 动笔前先确认（缺一不动笔）

- 覆盖口径：完整记录型（所有方法论、实践逐条记录）还是摘要精选型（只挑高价值条目）。两者结构和篇幅差数倍，用户没说就先问
- 读者与用途：自用知识沉淀、团队分享、决策支撑，决定细节展开深度和外链粒度

## 骨架

1. 结论先行：开头给核心结论清单，每条带适用边界
2. 分模块正文：每模块固定四件套——做法描述（展开到可照着复刻）、关键设计取舍、证据、边界
3. 认知修正表（调研推翻既有认知时必设）：原认知 / 核实结果 / 修正后表述三列
4. 可操作启示：把结论翻译成可执行规则，每条注明依据见第几节

## 证据纪律（本模板核心，逐条硬性）

- 关键结论必须挂来源：逐字原文引用（英文原文 + 中文译文）+ 可点击 URL；改写后的话不得当引用呈现
- 数字给出处，能定位到章节或页码就给到；不同任务不同口径的数字不排成同一张榜单
- 每节末标注证据强度，四档：实验数据 / 官方文档断言 / 论文附带观察 / 二手转述
- 结论带机制：只说 X 更好不合格，要说为什么（原理层解释），每个机制尽量各挂一个来源
- 搜不到权威信源明确写无法核实；有适用限度的结论补一行边界；严禁编造 URL、数字、论文名
- 每个主要模块配一个理解案例（来源原文实例或忠实抽象示例，标明是哪种）

## 配图

涉及结构化表达、层次化内容（流程、分层、树状、闭环、对比选型）时默认配一张图辅助理解。飞书落地为 SVG 画板，风格与字号按使用者自定义的画板规范统一执行；本地 markdown 阶段可用 mermaid 或画板占位注释。
