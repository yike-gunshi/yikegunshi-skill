# 场景模板：策略迭代说明

适用：一轮策略迭代（预发分支、模型替换、信息注入等）在固定回归集上的效果评测说明，面向产品、研发和老板，作为本轮收益结论与改动溯源的单一出处。

## 固定骨架（7 个 H1 平铺，顺序锁死，无嵌套）

1. `# 背景`：一段讲清测什么。圈定的回归集、验证的预发分支（行内 code）、判定方式与终版结论敲定日期，逐 case 明细挂链接
2. `# 评测`：bullet 列评测集构成（条数与来源拆分）、评测输入、评测结果、判定 Prompt，全部链接化不复述
3. `# 效果`：即结论区。首句给总修复数（加粗）与口径限定，后接效果主表
4. `# 改动说明`：溯源到 commit 级。表格列出分支、改动模块、改动说明、改前后效果，预发环境名与 commit hash 用行内 code
5. `# 记录`：原始附件区。新建评测集贴 csv/xlsx 原始附件，评测记录贴平台链接，评测环境用引用表（预发环境、说明、备注文档）
6. `# 问题`：本轮评测方案暴露的待复核问题，一行现象加复核文档链接
7. `# 已知问题`：编号列表逐条写现象加建议动作，沉底

## 效果主表写法

- 固定 6 列：一级问题、二级问题、数量（占比）、本次优化、具体实现、问题分析
- 全量问题分类都进表：未迭代模块的本次优化、具体实现、问题分析三列统一填横线占位，表格保持完整，覆盖面一眼可见
- 修复数加粗并带变化量（9/15 加 -60pp 式），不出现孤立数字
- 具体实现落到预发环境名（行内 code）与改动描述；问题分析写修复集中在哪、未修复集中在哪
- 合计行给目标模块修复率与占全量比例，标注分类框架的出处链接
- 含合并单元格时整表用 HTML table

## 语气要点

- 评测报告体：结论先行，口径限定严格。其余类目非本轮优化目标、判定口径以终版为准，这类限定语显式写出，防止读者把局部收益读成全局收益
- 问题分析必须有 action 指向：建议与研发核对该预发分支各模块合入状态；可接受口径待产品定义。只描述现象不给去向的分析不合格
- trace、评测集、结果链接只用真实存在的，一律不编造；拿不到链接就写待补，不放占位假链接
- 对外文档不露出考点二字，判定方式写端到端评测加人工 review 即可

已知问题的形态：

> 1. 构造 Query 部分单次 run 结果有波动（历史 3 次 run 不稳定），重要结论建议 2-3 次取多数。
> 2. 新回答引入的新事实断言需外部核验：本轮做了联网核查（60 条断言：属实 20 / 部分属实 18 / 有误 7 / 无法核实 10 / 行为类 5），无法核实多为平台内部规则、无公开信源。
