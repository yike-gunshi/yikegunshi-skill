# 场景模板：评测结论

适用：badcase 回归、迭代效果验证等评测文档的结论层，即口径声明、汇总统计、结论呈现的写法，面向老板和研发的判定交付。边界：case 逐条明细的排版（上下文、对比表、归因、trace 排布）归 lark-case-detail skill，本模板不管；读范文时 case 明细部分只作理解上下文用。

## 固定骨架（顺序锁死）

1. 文档头口径 blockquote：评测范围与条数、判定基准（以哪个评测结论为准）、人工 review 规则、基线定义、终版时间。防误读是第一优先级：读者先知道数字怎么来的，再看数字
2. 口径来源表：每类问题一行，列问题类型加条数、口径来源、实验环境（如预发环境名）、端到端实验链接
3. 标注图例：一句话说明 case 标题里每个结论符号的判定含义（✅、❌、⚠️ 各等于什么），紧跟口径区
4. 问题分区（H1，中文序号）：标题带问题类型、条数、实验环境。分区第一个元素是分组统计表（分组、总数、修复数、未修复数、修复率），结论前置，末行合计加粗
5. 统计表之后接逐条 case（H3），标题内嵌结论符号形成可扫读目录；标题以下的明细排版归 lark-case-detail

## 模块写法

- 口径 blockquote：关键判定词加粗（条数、以什么为准、基线定义）；review 流程写成规则句（与端到端结论不一致的转人工 check）；终版时间必写，让读者知道统计还会不会变
- 修复数的口径写进列名（如 修复（人工review终版）），不留读者猜是谁判的
- case 标题一行四段，全角竖线分隔：Case 编号、结论符号加结论词、query 截断、问题短语。问题短语压缩到 10 字内。结论全部前置到标题层，扫标题即得全貌，明细供抽查
- 每条结论一句话点死问题：主语加动作加错在哪（加入了无来源的精确结论），不铺垫不缓冲
- 模型原始输出完整保留不删节，原文里的符号、格式照留（保真引用例外）
- 对外评测文档不露出考点二字，改说历史问题、优化目标
- trace 和实验链接只用真实存在的，不编造；拿不到就写明无（如：历史未跑端到端）

## 语气要点

- 判定书体：零情绪零修饰，不写可惜、遗憾、值得肯定，满意与不满意都是一句话陈述
- 未修复照写不软化，0% 修复率原样进表
- 数字口径处处显式：基线是哪天、修复数谁判的、哪些条互不重合，全落在口径区和列名里
- 结论词收敛成固定枚举（已优化、未优化、待人工），全文不换说法
