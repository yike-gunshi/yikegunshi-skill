# 场景模板：指标需求

适用：指标口径的沉淀与传递文档。两个子形态按读者选：读者要查数据（自己或协作方查口径、找看板、排查数据对不上）用子形态一查询手册；读者是 DA 或数仓，要接需求干活（建指标、建底表）用子形态二提需论证。同一个业务两者可以都写，手册沉淀已建成的，提需推动未建成的。

## 子形态一：查询手册

### 骨架（顺序锁死）

1. 先验评估：人工评估类指标一张三列表（名称、关注指标、数据地址或查看方式）
2. 数据指标：章节头一个 callout 集中放口径说明，后接重要指标表
3. A/B 实验核心指标组：全文档主体，一张大表
4. Q&A：读者高频疑问
5. 数据异常问题找人流程
6. 附录：数仓文档等延伸材料

### 写法

- 文档组织是查询型不是阅读型：按使用场景分区（做评估看先验、看大盘看数据指标、开实验看指标组、对不上数看找人流程），读者带着问题跳到对应区，不必从头读
- 指标表三列式：指标名、口径、数据地址，每个指标直链看板或指标组，不留自己去找的指标
- callout 集中放口径：业务口径文档链接、核心报表地址、重要口径提示；埋点 bug 用警示符号单列一行，写明影响哪些指标、哪个版本修复、修复上线日期，此前数据能不能参考
- 实验指标组表七列：分类、模块、指标组（直链）、状态、指标说明、可拆解维度、备注。状态写可用及生效日期（可用（自2026/7/27起）），未开发写 - 不留空猜；非本团队维护的指标组在备注挂维护人 @人
- Q&A：问题加粗，答冒号开头一段讲完；枚举值多的答案（如渠道分类）直接进表
- 找人流程用 if-then 句式逐级写：先列自查步骤，自查完仍异常再联系谁（口径没问题，依然对不上，联系 @某人），每级只给一个出口

## 子形态二：提需论证

### 骨架（顺序锁死）

1. 头部 callout：现状（已有看板、建设中文档、埋点文档，全部链接化）加开发节奏（前置依赖、先出什么）
2. 一、背景信息：为什么现在提这个需求
3. 二、指标体系设计：分类框架与传导逻辑
4. 三、需求一指标体系：留存、规模、体验、基础数据四模块，每模块一张表
5. 四、需求二底表建设：链接到子文档
6. Todo 沉底：待对齐事项，checkbox 加 @人

### 写法

- 背景写三件事：缺什么指标、影响什么判断（策略同学无法参考数据定优先级）、现有数据为什么不能用（1% 采样不置信、两套口径对不上），有放量卡点也写在这
- 指标体系设计先给一句核心逻辑（体验优化 → 规模提升 → 留存增长），指标按能否指导做工分为可做工与监控两类；传导关系用箭头表达，设计理由放 blockquote（低频场景短留存波动大，30日口径最稳定，故重点攻坚 30 日留存）
- 每模块统一四列表：指标、定义与口径、分析目标、优先级 P0/P1。口径写到分子分母（搜索 UV / 输入框点击 UV），口径未定显式标注待定
- 分析目标列是文档的论证主体：写为什么要这个指标、拿到数据后怎么用它定位问题，让 DA 看一眼就知道轻重，不用来回问
- 不需要对方关注的部分显式标注（DA、数仓不关注）（下表数仓同学忽略），降低接需方阅读量
- 漏斗类指标先用一段 ASCII 图画出链路各节点，再按节点分表列指标

## 语气要点

- 表格即正文：两个子形态的信息主体都在表里，段落只做定调和过渡
- 口径写到可执行：分子分母、埋点字段、版本号、影响时间点写全，不写大概
- 警示不藏：埋点 bug、口径变更、采样不置信当场标注，写明影响范围和修复时点
- 主观判断带依据或降级词：埋点口径待确认、session 类指标口径待定
- 责任到人：指标组维护人、找人流程各级、Todo 对齐人都挂 @人
