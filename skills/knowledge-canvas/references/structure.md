# 内容、关系与证据

## 从读者的问题选择骨架

| 材料特点 | 优先结构 | 不应强加的结构 |
|---|---|---|
| 真实处理过程 | 主线、分支、汇合、循环 | 为版面整齐发明阶段 |
| 主题与子概念 | 分层容器、概念关联 | 把章节误当执行顺序 |
| 先修知识与推导 | 依赖图、论证链 | 把相关性画成因果性 |
| 同级方法或能力 | 容器内平铺、对照关系 | 无依据的逐个执行箭头 |
| 混合材料 | 按各部分语义组合 | 全图套用一种关系 |

先列清单：名称｜归属｜问题或作用｜主要内容｜关系｜适用条件｜证据。它帮助建模，不必展示成用户表格。

## 节点与层级

节点能独立解释一个重要概念、功能、判断或产物即可，不要求与函数、页面、段落一一对应。单纯胶水步骤用连线表达，重要原子节点仍在画布显式展示，不藏到 hover 中。

容器分别表示主题、职责或子系统，容器中的条目不自动意味着有执行顺序。名称用通俗中文，保留必要专业词；只有存在真实的英文名称时才展示英文副标题，不为凑格式发明调用名。

层级可嵌套，不强制固定数量。组件形态表达角色：动作、判断、文本产物、数据源可区分，普通概念使用简洁卡片或文本形态，不把所有概念画成数据库。

## 关系有两个维度

**类型：** flow 执行、data 数据流、dependency 先修或依赖、composition 组成、condition 条件、loop 回路、reference 引用。

**重要性：** primary 是读懂当前问题必需的主关系，secondary 是需要常驻的局部关系，auxiliary 是可按需显示的辅助关系。

两个维度独立。教材的先修依赖可能是 primary；实时输出通道虽然不在执行主轴上，也可能需要常驻。禁止按“全部 dependency 默认隐藏”这类固定映射删减理解所需的信息。

- 真正存在的顺序用有向线，标签写明流转、前提、支撑或引用的含义
- 并行关系分叉后汇合，不将并发分支画成串行
- 循环指向实际重复的起点，内层回路留在内部，外层回路沿容器侧边走
- 包含用容器表示，目录不必制造执行入口
- 多项组成一个产物时，用无箭头支线汇入公共线，只在出口放一个箭头
- 同一路径可以共用视觉线段，但每条原始关系仍保留在数据中，不能把不同条件合并掉
- 显示辅助依赖的开关只改变画线，不改变节点、关系记录、样例或布局

## 节点说明

按内容选栏目，信息够用即可：

- 处理功能：用途、输入来源、处理方式、产物、条件、与相邻节点的区别
- 知识概念：含义、核心观点、成立条件、关联概念、常见误解
- 方法或策略：适用问题、关键步骤、约束、产物与局限
- 数据或规则：包含什么、来自哪里、被谁使用、何时有效

解释机制与核心实现，不逐行转述代码；不把“精确”理解为堆满函数名、边缘参数或固定六条栏目。必要术语应连到当前材料中的具体例子。

状态分开处理：条件启用、默认关闭、当前范围不可用、样例未触发、证据不足。只有当前范围确实不可用才置灰，缺少材料或验证用独立提示。不能把“未验证”写成“不支持”。

## 按来源保留证据

- 代码：实现、配置、接口契约与运行记录各有证明范围，代码存在不等于部署或触发
- 书籍、PDF：保留章节或页码，区分原文主张与整理者的概括
- 课程：区分知识前提、讲解顺序和应用步骤
- 文档合集：术语归一后仍保留来源冲突，不静默选边

样例按节点独立选择，不要求一个案例覆盖全部内容。优先原文或真实记录，缺少时使用有标签的构造／推导示例，或明确证据缺口。

处理过程可有输入和输出；概念可有情境、例子、反例；论证可有前提和推导。不要为补齐模板伪造输入输出。

原始样例先选择合理范围，再保留选中内容的完整值。长文本可滚动，不用省略号替换。脱敏、翻译、改写后明确标注，不能继续称作原始值。采样和展示服从用户权限、隐私及版权要求。

FAQ 收录用户真实疑问、已确认答复或有材料依据的易混淆点，记录来源或关联节点，不编造用户问过的话。未解决的问题明确保留未确认状态。
