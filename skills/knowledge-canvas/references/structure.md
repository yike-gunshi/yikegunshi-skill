# 内容与关系建模

## 粒度

从用户要理解的问题出发。关键最小单元应能独立说明作用、输入或依据、产物或结论；不等同于函数、代码行或段落。每个容器代表一个明确功能、主题或归属，内部可继续分层。

先写节点清单：名称｜父容器｜作用及产物｜关系｜条件｜证据。这张工作清单用于推理和确认，不必复制到成品界面。

## 关系与版式

| 关系 | 表达 |
|---|---|
| 执行顺序、数据流 | 有方向的连线，标注必要产物 |
| 并行、条件分支 | 有依据的分叉和汇合，条件写清 |
| 循环 | 指回实际重复步骤，不额外发明“推进下一轮”节点 |
| 包含、同级能力目录 | 容器内平铺，不互相连执行箭头 |
| 知识依赖、论证支撑 | 连线标明“前提”“支撑”等语义，避免误读为时间顺序 |

有真实执行入口的模块保持入口与主线可追踪，可以一对多；资料库、工具目录等容器不需要制造执行入口。横纵对齐可用于同级项目，但整体布局应显露结构差异。

大模块用易懂且稳定的名称，不把实现细节堆进标题。用户已接受的专业名词保持稳定；具体项目的场景、名称和 Trace 边界不成为其他材料的默认骨架。

## 按材料找证据

- 仓库：入口、消息或数据模型、配置、核心调用和条件分支；源码事实与部署运行证据分开
- PDF、书籍：章节、定义、论点、推导、案例、前提；引用页码或章节，不臆造输入输出接口
- 课程：学习目标、先修概念、步骤、练习和结果；区分讲解顺序与概念依赖
- 文档合集：统一术语及重复信息，保留冲突与来源，不静默选定争议信息

对于知识类节点，输入可以是原文材料或问题，输出可以是原书示例、作者结论或明确标注的整理结果；来源没有给出的内容不伪装为原文。

## 范围与状态

可用范围和实际调用是两个维度。目录属于当前场景，通常显示；本次 case 未调用，不足以判断不可用。范围外条目仅在用户要求比较目录时展示并置灰。条件启用和默认关闭保留条件说明；缺证据不能推导成不支持。

预加载、自动加载、按需调用等名称只有在材料确实存在相应机制时使用。首次与后续过程共用逻辑时优先一个节点，入口与回流分别表达。

## 样例证据

每个节点可有独立 case。选择能说明该节点效果的输入和输出，关联字段保持一致。来源记录在详情底部，注明实际运行、原文或代码固定值、代码推导、构造示例。

选择展示哪些字段可以讨论，但选中的字段值完整保留。不要把整个 Trace 无差别塞进每个节点，也不要用概括性语句替代用户要求的原始字段。提供的样例不足时，以代码契约解释尚未观察的部分，不能把契约当作真实输出。

版本与时间仅用于界定证据。默认解释当前已核验状态，不主动增加旧版对照。一个场景或仓库的事实不泛化到其他场景或整个平台。
