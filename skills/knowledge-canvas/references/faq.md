# FAQ：直接解答、机制解释与节点联动

适用于知识画布中 FAQ 的新增、改写与交互维护。遵循用户已确认的阅读目标；用户要求先讨论时只给文字或局部关系样稿，不先修改网页。

## 阅读目标

- 默认第一目标：让读者能向别人讲清当前系统怎样运行，或当前概念、方法与论证怎样成立
- 第二目标：理解改变行为或前提时可以调整哪里、会牵涉什么；系统材料可写改动入口，知识材料可写适用条件与应用限制
- 保留原问题中的机制、职责边界和分类关注点，不能为方便作答换掉问题本意
- FAQ 在当前页应能独立读懂，节点跳转供深入阅读，不要求用户自行拼接答案
- 用户未要求诊断时，不以定位原则、判断原则、核对日志等检查步骤代替直接答案；明确请求排查的问题可以保留诊断主线

## 内容分层

按问题选用以下层次，不凑固定条数或每页固定栏目。

1. **直接答案**：用少量文字回答有没有、是什么、谁负责、何时成立，影响结论的关键条件一起展示
2. **核心机制或关系**：处理过程讲谁获得什么信息、怎样处理、产出交给谁；概念与论证讲关键含义、关系、前提与结论，不强加执行顺序
3. **关键说明**：补充职责、适用边界和易混淆点，避免重新抄一遍节点定义
4. **样例或原文**：先说明这个例子展示什么，再呈现选取范围内的完整输入输出、原文、情境或推导
5. **关联节点**：在相关说明旁或文后引用真实节点，供单点定位或整组查看
6. **如何调整或应用**：有依据时作为次级内容，网页默认折叠，说明入口、范围、限制及可能影响，不为纯概念问题编造改代码建议
7. **依据与范围**：列来源、版本和未核验边界，可折叠；直接影响答案的条件仍须在主内容可见

规则或配置规定的期望行为、实际发生的行为和效果评价分别表达。例如，规则存在不能证明执行遵守；样例有输出不能证明结果正确。区分信息准备、决策、执行与结果，不把它们的职责混在一起。

写法沿用 presentation.md 的加粗要点加正文和分层列表。无需把一句话能解释清楚的内容拆成多个标题，关键说明不只放在 hover。

## 样例与证据

- 先选择对当前问题有解释力的范围，再保留选中原文或字段的完整值；选取部分消息时明确说明，不能称作完整输入
- 保留原格式、转义、空白和字段值，不用省略号或总结替代，长内容通过滚动阅读与复制
- 不强制一个 case 贯穿所有问题，不能把多个 case 拼成一条真实执行记录
- 真实记录、代码原文、书籍原文、代码推导和构造情境分别标注；没有运行证据时用契约或原文解释，不伪造日志
- 源码版本、运行记录对应版本与资料章节分开说明，历史样例不能冒充当前部署或普遍规律
- 不把规则调整影响模型行为与代码控制确定性流程混为同一类改动，影响范围只写材料支持的部分

## 选择轻量表达

优先采用短步骤、段落及可点击节点标签，避免重复维护已有画布。流程图适合必要的分支、汇合和循环；对照表适合职责或条件差异；概念图适合关系和前提。结构由问题决定，不强制表格或 SVG。

在含多条 FAQ 的页面中，目录选中一个问题后显示该问题正文。保留已认可的目录与阅读交互；采用侧栏时，长标题单行省略，悬停或键盘聚焦展示全文，支持拖动分隔线调整宽度并提供键盘等效操作，窄屏避免挤压正文。

## 与画布关联

先核对节点映射，引用使用已有节点 ID 与真实显示名称，不能为 FAQ 捏造一套同义节点。过程产物、状态或阶段简称可能只是解释标签，应关联产生或使用它的现有节点，不假装它已是独立节点。节点可以是逻辑抽象，不要求一一对应函数、文件或日志片段。

- **单节点查看**：点击名称，进入画布定位并突出该节点，可查看详情
- **整组查看**：需要展示本题整体关系时，提供“在画布中查看本题”（流程型可称“链路”），高亮相关节点和有依据的已有连线，其余内容降低对比但仍可见，不凭空补出新关系
- **可读定位**：优先定位核心区域，跨度大的关联项继续标记或提供导航，不强行缩小到全部塞入一屏；整组查看不自动弹详情遮挡关系
- **返回阅读**：提供返回 FAQ 与浏览器回退/前进，恢复问题、滚动位置和展开状态；保留画布视角，退出本题聚焦时清除临时高亮
- **清晰语义**：节点顺序、依赖与包含关系以材料为准，多个来源共同组成输入时不能画成逐个执行

当前通用模板的数据入口为 faq.question、faq.answer、faq.nodeIds、faq.source，已有基础问答和单节点定位。上述目录、原文样例展示、阅读回退及整组高亮是交互 FAQ 的维护目标，不能假定模板已全部实现。实际生成或改交互时检查目标页面的支持情况，按已确认需求补齐数据、渲染与测试，不能仅添加未被读取的字段就声称功能完成。纯内容维护不自动重构整个模板。

## 增量维护与验收

- 延续已有问题、证据、节点 ID 与读取状态，精准修改当前需求范围，不重画无关链路、不改写原始样例
- 首次重写表达方式且用户要求预览时，选有代表性的样稿供确认，数量与深度服从用户要求
- 内容验收：第一段回答原问题，主内容足以讲清机制或关系，关键条件可见，链接目标准确，次级改动建议有依据
- 交互验收：实际测试问题切换、长标题、目录调宽、单点与整组定位、返回/前进、滚动和展开恢复、窄屏、原文复制；只报告真正实现并验证的项
- 通用性验收：系统或流程问题能说明输入处理输出；概念或教材问题能说明前提、关系与例子，不被迫改造成软件运行流程
- 写法规范与交互实现分别报告，维护说明文件不代表网页功能已经上线或通过浏览器验证
