# book-to-mindmap — 书与长笔记转思维导图

把长内容重组成一张能扫一遍掌握主张、点开才看细节的导图。核心不是格式转换，是信息结构重组，决定哪些内容留在节点上、哪些沉进解释、哪些直接删掉。

配套文档，按需要读：

| 文档 | 什么时候读 |
| --- | --- |
| `references/writing-rules.md` | 写节点前必读，压缩措辞是手艺，只靠规则条款学不会 |
| `references/long-book.md` | 处理整本书、或原文超过五万 token 时 |
| `references/non-narrative.md` | 原文含公式、代码、表格、图表、实验、习题时 |
| `references/coverage-check.md` | 交付前查遗漏时 |
| `references/xmind-style.md` | 想调 .xmind 的样式或用新字段前，先看哪些实机验证过、哪些是坑 |
| `references/methodology.md` | 想改规则前，先看这些规则是怎么来的、哪几版被否过 |

## 一条知识分两层放

导图上看得见的是**节点**，点开小图标才看到的是 **notes**。两者分工不同：

| 位置 | 放什么 | 长度 |
| --- | --- | --- |
| 节点 | 一句可判真假的短判断 | 5-18（中文字符记 1、英文单词记 1） |
| notes | 机制解释、数据、边界条件，写成完整自然句 | 不限，能独立读懂即可 |

导图视图横向展开，长句节点会把画布撑爆；但把解释删掉，读者又得回原文。notes 正好解决这个矛盾。

生成 .xmind 时，**notes 的第一段会自动以灰字显示在节点内部**，不用点开就能看见。所以第一段要能独立成立，把最关键的机制放这里，展开和数据放到后面几段。

**第一段控制在 60 字上下**，中位落在 55-70 就对了。它在节点里折行，60 字约两行，88 字要三四行，几十个节点叠起来画布就挤。写超了把后半截拆成第二段，别为了压数字截断句子。

只有第一段的 notes 不会挂图标（点开看到的是同一句话，图标是噪音）；有第二段才挂，图标从此表示"还有更多"。

**量长度必须跑 `scripts/inline_stats.py`**，它和生成器用同一套切分逻辑。凭印象数、或者只数节点后的第一行，结果都会偏小——首段可能跨多行。转十章时有三个 agent 在这件事上报了假数字，根因是拿节点标题的长度口径去量 notes。

判断一段内容该去哪，问它能不能改变读者的判断或行动。能，写成节点；只是帮助理解某个节点，写进 notes；两者都不是，删。

渲染样式（颜色、宽度、布局、分支配色）全部记在 `references/xmind-style.md`，那是唯一权威，脚本里的常量与它一一对应。

## 骨架规则

**一章一张画布，多章合成一个 .xmind 文件**，用 `scripts/combine.py` 合并，各章的 .md 仍是各自独立的真源。单章内部不要再拆画布，跨表跳转会切断整体感。

规模靠折叠控制，生成时折叠到第 2 层，打开先看到骨架。

分支数量跟着内容走，不要凑数也不要硬砍。真有八九个并列主题就写八九支，只有三块内容就三支。检查脚本里的层深和分支数只是提示，超了先想想是内容确实如此还是自己没分好组。

**根节点也要交付一句主张**，挂在它下面的 `> ` 行里，折叠态第一眼就知道这章讲什么。只写书名或章名等于浪费掉最显眼的位置。

一级分支怎么划，按优先级：

1. 书自带强框架（四要素、五阶段、N 条法则）直接用作分支
2. 按核心问题重组，用读者视角的疑问
3. 章节忠实，仅当作者结构本身就是层层收束的论证时才用

章节顺序是作者的叙事需要，不等于知识结构。目录书里已经有了，导图照抄目录就没有增量价值。

原文里的配套实验和思考题单独收一支放在末尾，别打散进各分支——它们是学习资源，和知识主干的读法不一样。

枝干要写成判断，不能是话题标签。「失效模式」只宣告下面有内容，自己不交付任何知识；「模型偏向上下文两端，忽略中间」读完就有收获。判断用自然句写，句式随内容变化，同一层的兄弟节点不要清一色套同一个格式。

写完一个分组自检一次：问自己这些子节点合起来说明了什么，答案应该正好是父节点那句话。答不出来说明分组错了；父节点删掉读者也毫无损失，说明它是个空标签。

## 节点措辞

- 完整自然句，不用电报体缩略。「中部易丢」「即冻结」这类压缩读起来像密码，省的那几个字不值得
- 复合句拆层：主结论做父节点，原因和展开挂子节点，关系交给导图连线表达
- 信息（现象、机制、事实）和做法（该怎么做）分成两个节点，做法挂在推出它的信息之下，加「做法：」前缀
- 流程类内容用「第 X 步：」前缀，一步一节点
- 术语首次出现带中英对照，如「注意力储存池（Attention Sink）」
- 节点末尾不加句号
- 不用「不是…而是…」句式，改成正述加补充。这是用户的长期偏好，节点和 notes 都适用
- 每个节点标一个关键词，用 `**术语**` 包起来，生成时换成蓝色。标真正的术语或关键数字，一个节点最多一处——标多了等于没标。标题和 notes 里都能标

notes 的文风对齐原书行文。转换前先读几段原文，摘出它的句式特征——怎么连因果、怎么解释术语、用什么强调结构——照着写。这比套任何通用模板都自然。

## 覆盖度分档

开工前定一个档，它决定筛选的松紧，也决定要不要做遗漏检查：

- **精读替代版**（用户没读过原文、想靠导图学会）：章节里所有实质内容都要有位置，包括配套实验、数据、习题考点。只删过渡句和重复表述。交付前必须做遗漏检查
- **蒸馏版**（用户读过，导图用来复习和检索）：按下面的筛选序压到主干

不确定就默认精读替代版。用户说"我没读过这章想快速学"时，删掉的东西他根本不知道自己错过了。

筛选序（蒸馏版用），按保留优先级从高到低：

1. **判断规则**——"遇到 X 就做 Y，因为 Z"，作者的 if-then 逻辑
2. **决策树与取舍矩阵**——多于两个分支的选择，以及竞品在各维度上的对比
3. **阈值与默认值**——作者给出的具体数字和经验取值
4. **识别征兆**——"看到 X 说明多半有 Y 问题"这类快速启发
5. **机制**——为什么会这样
6. **现象与例证**——最先被删的

执行时：删掉后既不改变理解、也不改变行动的句子，删；同一原则在原文多处出现只保留一条；过渡句默认删；有价值但非主干的解释降级进 notes。

## 工作流

**0. 普查。** 跑 `scripts/book_survey.py 全文.txt`，拿到章节切分、各章字数和元素清单（公式、代码、表格、图表、实验、习题各多少）。这张表是最后对账用的。脚本报的提示要看，章节切分骗人是常事。

**1. 读。** 短文档直接通读。整本书或超过五万 token 的，走 `references/long-book.md` 的切片读法，不要无界整篇读。不通读就划不出真正的知识结构，只会退化成章节复刻。

**2. 定骨架，先给用户看。** 只写一级分支和枝干，每支一句能交付判断的名字，子节点留空。这一步是门禁——骨架错了往下填只是把错误铺开。用户确认前不要展开。

**3. 一支一支填。** 每支写完跑一次自检。原文里的非叙事元素按 `references/non-narrative.md` 安置。

**4. 回填 notes。** 节点全部定稿后再写解释，避免一开始就陷进细节。

**5. 查遗漏。** 跑检查脚本，再按 `references/coverage-check.md` 做覆盖检查。精读替代版必须做到第二层的问答验证。

**6. 交付。** 生成 .xmind。用户要发飞书时，用 `lark-cli docs +update` 发多级 bullet 版。

分章派给子 agent 时，**它报的数字一律自己重跑一遍再信**。转十章时三个 agent 都报了假的长度数字，不是撒谎，是各自用了不同的量具。同样要自己抽查的还有：溯源标签有没有编出原文不存在的编号、关键词是不是标了描述性短语而非术语、以及去掉 `**` 后的正文与改动前是否逐字相同（改写类任务用这招验内容有没有被悄悄改掉）。

## 真源格式与脚本

真源是多级 bullet Markdown，2 空格缩进一层。节点行后面的 `> ` 行是 notes，行尾的 `@` 是标记、`§` 是溯源章节号：

```markdown
- 书名：一句总主张
  - 模型偏向上下文两端，忽略中间 @核心 §2.1
    - 做法：关键规则放开头，最新结论放末尾
    - 首 token 是注意力储存池（Attention Sink） §2.1
      > Softmax 要求注意力总和恰好等于 100%，模型无法"不关注任何东西"。
      >
      > 多余的注意力被集中存放在序列首 token 上，**有时超过总注意力的 70%**。
      > - 这是系统性现象，不是模型缺陷
```

notes 支持分段和 `- ` 列表。

`§` 溯源标签**挂在一级分支上**，标明这支对应原文哪一节，让"不编造"这条红线可以对账。个别节点跨节时可以单独挂。

`@` 标记按语义分工，全章用量控制住，否则图标满屏就失去指示作用：

| 标记 | 用在什么节点 | 全章用量 |
| --- | --- | --- |
| `@核心` | 全章最该记住的主张 | 3-5 个 |
| `@注意` | 作者点名的易错点、反直觉结论 | 按需，通常 5-15 个 |
| `@数据` | 承载实验数据或关键数字的节点 | 按需 |
| `@已验证` | 你自己动手跑过、确认过的结论 | 按需 |
| `@问题` | 存疑或原文没交代清楚的地方 | 按需 |

```bash
python3 scripts/book_survey.py 全文.txt              # 转换前普查
python3 scripts/mindmap-lint.py 真源.md              # 结构检查
python3 scripts/md2xmind.py 真源.md 输出.xmind 2     # 单章，末位是折叠层深
python3 scripts/combine.py 全书.xmind 2 -- 第1章.md 第2章.md   # 多章合成，一章一画布
```

检查脚本只硬管两件能程序判定的事：节点长度和句末标点。其余只打印提示，由你判断：**模板腔**（兄弟节点句式雷同）和**过度分析**（大量只带一个子节点的父节点）一定要改；层深和分支数超了则先想想是内容确实如此还是分组没做好。

真源是唯一可编辑的东西，.xmind 是产物，改内容要改真源再重新生成。**XMind 不会重载已经打开的文件**，所以给用户看新版时换个文件名放到 /tmp；不要用 osascript 强制退出 XMind，试过一次，退出后应用起不来了。

## 验收

脚本通过只说明格式合规。质量看这四问：只看折叠态的骨架能否复述全章主张、任意节点能否独立回答"我需要记住什么"、点开 notes 能否读懂机制、相邻节点有没有同义重复。

覆盖是另一回事——四问全过仍可能漏掉半章，漏掉的部分不会举手。走 `references/coverage-check.md`。

## 两条红线

- **不编造**。节点和 notes 的每一条都要能在原文里找到出处。在导图里写下某个框架名之前，先 `grep` 一次确认作者真的讲过它。导图是压缩，压缩不该产生原文没有的信息。
- **不覆盖**。飞书页面、已有 .xmind、已有真源，改动前先确认，或新建一份给用户对比。旧版是用户的历史资产，删了找不回来。
