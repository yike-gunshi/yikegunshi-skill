# book-to-mindmap — 书与长笔记转思维导图

把长内容重组成一张能"扫一遍就掌握主张、点开才看细节"的导图。核心不是格式转换，是**信息结构重组**：决定什么进图面、什么降级、什么删掉。

方法论依据与失败史见 `references/methodology.md`；节点措辞的正反例见 `references/writing-rules.md`（写节点前必读，压缩措辞是手艺，只靠规则条款学不会）。

## 三层信息密度

这是整套方法的地基。一条知识拆到三个位置，各司其职：

| 位置 | 放什么 | 长度 |
| --- | --- | --- |
| 图面节点 | 一句可判真假的短判断 | 有效长度 ≤18（中文字符记 1、英文单词记 1） |
| notes | 机制解释、数据、边界条件，完整自然句 | 不限，写成能独立读懂的段落 |
| 子节点 | 与父节点构成推理关系的下一层判断 | 同图面 |

为什么这样分：导图视图横向展开，长句节点会把画布撑爆；但把解释直接删掉，读者就得回原文。notes 让图面保持清爽的同时不丢信息——它是 XMind 的一等能力，节点角上出现小图标，点击悬浮展开。

判断某段内容去哪：**它能改变读者的判断或行动吗**。能，进图面；只是帮助理解某条图面判断，进 notes；两者都不是，删。

## 骨架规则

**一本书 = 一张画布**。根节点是书名，一级分支 5-8 支。不要拆成多张画布——跨表跳转会切断整体感。规模靠折叠控制：生成时折叠到第 2 层，打开先看到"根 + 一级分支 + 枝干"约 40 个判断的骨架。

**一级分支怎么划**，按优先级：

1. 书自带强框架（四要素、五阶段、N 条法则）→ 直接用作分支
2. 按核心问题重组（读者视角的疑问）
3. 章节忠实 —— 仅当作者结构本身就是层层收束的论证时才用

章节顺序是作者的叙事需要，不等于知识结构。目录书里已经有了，导图照抄目录就没有增量价值。

**枝干必须是判断，不是话题标签**。「失效模式」只宣告下面有内容，自己不交付知识；「模型偏向上下文两端，忽略中间」读完就有收获。判断写成自然句即可，「关键词：短判断」的冒号式只是可选写法，用在术语确实需要当路标时（如 Mem0、RAPTOR）——同一层的兄弟节点不要清一色套同一个句式，那是模板腔，读起来像机器生成。

**自检**：每个父节点问一句"子节点合起来说明什么"，答案要等于父节点文字。答不出来，说明这组分错了；父节点删掉后读者毫无损失，说明它是空标签。

## 节点措辞

- 完整自然句，不用电报体缩略。「中部易丢」「即冻结」这类压缩读起来像密码，省的那几个字不值得
- 复合句拆层：主结论做父节点，原因和展开挂子节点，关系交给导图连线表达
- 信息（现象、机制、事实）和做法（该怎么做）分成两个节点，做法挂在推出它的信息之下，加「做法：」前缀
- 流程类内容用「第 X 步：」前缀，一步一节点
- 术语首次出现带中英对照，如「注意力储存池（Attention Sink）」
- 节点末尾不加句号

notes 的文风对齐原书行文——转换一本书之前先读几段原文，摘出它的句式特征（怎么连因果、怎么解释术语、用什么强调结构），照着写。这比套任何通用模板都自然。

## 覆盖度：先问这张图要不要替代原文

开工前定一个档，它决定筛选的松紧：

- **精读替代版**（用户没读过原文、想靠导图学会）：章节里所有实质内容都要有位置，包括配套实验、数据、思考题。只删过渡句和重复表述
- **蒸馏版**（用户读过，导图用来复习和检索）：按下面的筛选序压到主干

不确定就问一句，或者默认精读替代版——用户说"我没读过这章想快速学"时，删掉的东西他根本不知道自己错过了。

筛选序（蒸馏版用）：**判断规则 / 行动 / 阈值 > 机制 > 现象 > 例证**。

- 删除测试：删掉后既不改变理解、也不改变行动的句子，删
- 同一原则在原文多处出现，只保留一条
- 过渡句默认删；有价值但非主干的解释降级进 notes

## 工作流

1. **读全文**。长文档分段读完再动手，不要边读边写——不通读就划不出真正的知识结构，只会退化成章节复刻。
2. **定骨架**。按上面的优先级划一级分支，每支起一个「关键词：短判断」的名字，先跟用户对一次骨架再往下填。
3. **填枝干与节点**。一支一支写，每支写完跑一次自检。
4. **写 notes**。图面定稿后再回填解释，避免一开始就陷进细节。
5. **验收**。跑 lint，再做体验验收（下一节）。
6. **交付**。生成 .xmind 交付；用户要发飞书时，用 `lark-cli docs +update` 发多级 bullet 版。

## 真源格式与脚本

真源是多级 bullet Markdown，2 空格缩进一层，节点行之后的 `> ` 行是该节点的 notes：

```markdown
- 书名：一句总主张
  - 注意力：模型偏向两端，忽略中间
    - 做法：关键规则放开头，最新结论放末尾
    - 首 token 是注意力储存池（Attention Sink）
      > Softmax 要求注意力总和恰好等于 100%，模型无法"不关注任何东西"——多余的注意力被集中存放在序列首 token 上
```

```bash
python3 scripts/mindmap-lint.py 真源.md              # 结构检查
python3 scripts/md2xmind.py 真源.md 输出.xmind 2     # 末位是折叠层深，2 = 打开先看骨架
```

lint 查的是可程序化的部分：图面长度 5-18、浅层分支 ≤8、深层 ≤5、层深 ≤4、句末标点。真源是唯一可编辑的东西，.xmind 是产物，改内容改真源后重新生成。

## 验收

lint 通过只说明格式合规，说明不了读起来怎么样。交付前自己走一遍这四问，有一条不满足就回去改：

- 只看折叠态的骨架，能否复述全书主张
- 任意图面节点能否独立回答"我需要记住什么"
- 点开 notes 能否读懂机制，不用回原文
- 相邻节点有没有同义重复

## 两条红线

- **不编造**。图面和 notes 的每一条都要能在原文里找到出处。导图是压缩，压缩不该产生原文没有的信息。
- **不覆盖**。飞书页面、已有 .xmind、已有真源，改动前先确认，或新建一份给用户对比。旧版是用户的历史资产，删了找不回来。
