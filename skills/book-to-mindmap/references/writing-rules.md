# 节点措辞：正反例对照

压缩措辞是手艺，不是规则条款能覆盖的操作。下面每组都来自真实迭代——左边是被否掉的版本，右边是通过的版本。写节点卡住时翻这里。

## 一、电报体 vs 自然句

模型压缩中文时会本能地退化成密码式缩略，省下三五个字，读者却要花时间解码。

| 否 | 是 |
| --- | --- |
| 中部易丢 → 关键规则放开头 | 模型更关注上下文的开头和结尾，中间的信息容易被忽略 |
| 定稿即冻结 | 系统提示词和工具定义定稿后一字不改 |
| 关键状态显式提炼 | 关键状态要主动提炼成显式知识 |
| 状态栏 LLM 维护禁 | 状态栏用代码维护，别让 LLM 批量统计 |

判断标准：这句话念出来像不像人话。像电报、像标题党、像词组拼接，就重写。

## 二、复合句拆层

一个节点只承载一个短句。原因、展开、例证挂成子节点，关系交给导图连线表达。

否（一行 35 字，导图里是一条超宽节点）：

```text
- 时间、用户状态这类动态内容永远追加到对话末尾，用新消息更新而非改写前缀
```

是（主结论 13 字，展开下沉）：

```text
- 动态内容只在对话末尾追加
  > 时间、用户状态等变化的内容作为新消息追加到末尾，而不是修改已有的系统提示词
```

行内用「——」接原因也算复合句，同样要拆。破折号后的内容基本都属于 notes。

## 三、话题标签 vs 判断

枝干是被扫读得最多的一层，它必须自己交付知识。

| 否（只宣告主题） | 是（关键词 + 判断） |
| --- | --- |
| 工作原理 | 原理：前缀一变，之后全部重算 |
| 注意力规律 | 注意力：模型偏向两端，忽略中间 |
| 失效模式 | 失效：时间戳、动态排序、滑动窗口 |
| 架构约束 | 架构：缓存经济性是前置约束 |
| 实验证据 | 收益：弱模型补准确率，强模型省成本 |

冒号前 1-4 字管定位（在导图里找位置用），冒号后管交付（读完就有收获）。

## 四、信息与做法分节点

一句话里同时装着"世界是怎样的"和"你该怎么做"，读者要自己拆。拆好了给他。

否：

```text
- 模型更关注上下文的开头和结尾，中间的信息容易被忽略——关键规则放开头，最新结论放末尾
```

是：

```text
- 模型更关注上下文的开头和结尾，中间的信息容易被忽略
  - 做法：关键规则放在开头，最新结论放在末尾
```

做法挂在推出它的信息之下，连线本身就表达了"所以"。纯信息节点可以没有做法子节点，不必强行配对；在本身就是行动清单的分支里（铁律、原则），节点自己就是做法，不加前缀。

## 五、notes 怎么写

notes 是完整的书面段落，不是节点的扩写。它要能独立读懂，包含图面省掉的机制、数据和边界。

图面：`首 token 是注意力储存池（Attention Sink）`

notes：

```text
Softmax 要求注意力总和恰好等于 100%，模型无法"不关注任何东西"——多余的注意力被集中存放在序列首 token 上，有时超过总注意力的 70%
```

写 notes 前先读几段原文，摘出作者的句式特征照着写：怎么连因果（破折号？冒号？"因此"？）、怎么解释术语（先中文后括号英文？打比方？）、用什么强调结构（"一旦…就…"？"哪怕…也…"？）。文风对齐原书，读起来才像同一本书的延伸而不是 AI 摘要。

## 六、长度校准

有效长度 = 中文字符数 + 英文单词数。目标 15，lint 上限 18。

| 长度 | 判断 |
| --- | --- |
| < 5 | 太短，多半是话题标签，检查是否在交付知识 |
| 15 左右 | 理想区间 |
| > 18 | 拆层，或把后半句移进 notes |

英文技术词按词计，`使用标准 role-content API，不自行拼接` 是 12 + 2 = 14，合规。
