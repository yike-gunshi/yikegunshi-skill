# XMind 渲染实测记录

这份文档记的是**实机验证过的**渲染事实，不是文档推测。每一条都是在 XMind 里打开看过的。改样式前先读这里，能省掉重走一遍试错的时间。

## 定型的样式

这五个常量决定了导图的观感，全部在 `scripts/md2xmind.py` 顶部。改之前先看下面每一条的理由，它们都是对比过多个方案才定下来的。

| 常量 | 值 | 作用 | 为什么是这个值 |
| --- | --- | --- | --- |
| `INLINE_STYLE` | `{"fo:color": "#8A8A8A"}` | 节点内灰字 | 只设颜色，字号字重交给主题。缩字号加浅灰两个减法叠加会看不清；细体在中文字体上渲染不稳 |
| `INLINE_WIDTH` | `450` | 节点限宽 | 长句自动折行，不限宽节点会被拉成一条。300 试过偏窄 |
| `KEYWORD_STYLE` | `{"fo:color": "#2E6FD9"}` | 关键词强调 | 换色而非加粗，理由见下一节 |
| `BRANCH_COLORS` | 十色 `multi-line-colors` | 一级分支各一色 | 一章两百个节点时，颜色是最省力的定位手段——扫到一片蓝就知道还在同一支里 |
| `STRUCTURE` | `org.xmind.ui.logic.right` | 整图布局 | 技术书是层层收束的论证，逻辑图比默认的中心发散图贴合；实测真实文件里这个布局用得最多 |

配套的两条生成行为：

- **notes 第一段渲染进节点**成为第二行，完整 notes 仍在，点图标看全文；只有一段时不写 notes 字段，图标不出现
- **折叠层深默认 2**，打开先看到「根 + 一级分支 + 枝干」的骨架

超过十个一级分支时颜色会循环，这时靠 `§` 标签区分即可，不必为配色去合并分支。

## 三条踩过的坑

**富文本样式只认 `fo:` 前缀。** 节点内的分段样式写在 `attributedTitle` 里，每段是一个对象。样式键必须是 `fo:color`、`fo:font-size` 这种带前缀的写法；驼峰命名（`textColor`、`fontSize`、`fontWeight`）XMind 直接忽略，不报错，就是不生效。

这一条曾有两份调研给出互相冲突的答案，一份说驼峰一份说 `fo:` 前缀，都自称验证过。最后靠一个五变体对比文件判出来——同一份内容用两套命名各写一遍，在 XMind 里打开看哪个变灰了。**遇到这类冲突，做对比文件比继续查资料快。**

```json
"title": "判断句\n解释文字",
"attributedTitle": [
  {"text": "判断句"},
  {"text": "\n"},
  {"text": "解释文字", "fo:color": "#8A8A8A"}
]
```

`title` 必须是各段文字拼起来的纯文本，它是搜索和降级显示用的兜底。

**callout 气泡不能用。** `children.callout` 确实能渲染，但气泡浮在节点外侧、文字发虚，加上一屏几十个节点时视觉很乱。试过就废弃了。

**主次只用颜色分。** 试过缩字号、试过细体，结论是：

- 缩字号加浅灰两个减法叠在一起，字就看不清了
- `fo:font-weight: 300` 细体在中文字体上渲染不稳，不同字体表现不一致
- 只留颜色最干净，而且换主题时不会跟主题的字号打架

样式设得越少越好。每写死一项，就多一处和主题冲突的可能。

## 其他确认过的字段

- `structureClass: "org.xmind.ui.logic.right"` 写在 rootTopic 上，整图用逻辑图布局。技术书是层层收束的论证，比默认的中心发散图贴合
- `branch: "folded"` 只折叠节点自身，对子孙没有传染性，要逐个打标
- notes 必须同时写 `plain` 和 `realHTML` 两个字段。渲染读的是 `realHTML`（不是 `html`），`plain` 供搜索和第三方解析器
- notes 的 HTML 支持 `<div>` `<strong>` `<ul>` `<li>`，**不支持 `<code>`**
- `customWidth` 是数字（像素），控制节点宽度，长文本靠它折行
- 标记 ID 写错不会报错，XMind 原样保留但不显示任何图标，只能自己校验（见 `scripts/xmind_markers.py`）
- `theme: {}` 空对象是合法的，XMind 会套默认主题。不要手搓 theme 对象，那是十几个角色块的大结构，写一半会导致样式错乱

## XMind 不会自动重载已打开的文件

重新生成同名 .xmind 后，如果 XMind 里正开着这个文件，看到的还是旧内容。给用户看新版时**换个文件名放到 /tmp**。

**不要用 osascript 强制退出 XMind。** 试过一次，为的是绕开上面这个行为，结果退出后主程序再也起不来了——插件进程还残留着，清掉也没用，最后只能让用户手动从 Dock 点开。代价远大于收益。

## 关键词强调不能用加粗

XMind 主题里**节点标题默认就是粗体**，所以在标题里给关键词加粗等于没加，整句看着都一样粗。试过四种做法：整句默认加关键词粗（看不出）、其余压成常规加关键词粗（有反差但要动两处字重）、关键词换色（选中）、又粗又变色（过头）。

定型是换色：`KEYWORD_STYLE = {"fo:color": "#2E6FD9"}`。只动颜色一个维度，不碰字重，和灰字那套逻辑一致——每层视觉只用一个变量。

## 节点内灰字的长度

第一段控制在 60 字上下。450 宽度下 60 字约两行，88 字要三四行，节点会明显变高。实测对比：一份 58 字中位数的章节读起来舒服，另两份 88 字中位数的明显偏挤。
