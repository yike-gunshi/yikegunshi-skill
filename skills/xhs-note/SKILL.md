# xhs-note — 小红书笔记写作

产出四件：**封面图、标题、正文、标签**，外加一份归档。

## 定位与边界

写的是"一个自己做工具的独立开发者在跟同行交换经验"，不是推广文案。他的读者是同行，看得出吹牛。

边界之外的交出去：公众号长文和知乎长文交给长文写作 skill，发布动作交给 wechat-publisher 和 x-article-publisher，纯 prompt 撰写交给 prompt-craft。

## 先分体裁

他的笔记有两种，节奏几乎相反，开工前必须先认清是哪种。认错的代价实测过：2026-08-03 那篇感悟帖，AI 拿工具帖的节奏写了四版，一版没用上。

**工具分享帖**——他做了个东西，配截图，跟同行说这东西怎么用。范文 `2026-08-01-forge-bugfix.md`、`2026-08-02-forge-fupan.md`。特征：短段落、段落式小标题、编号清单是主体、签名句式「我要做的事情就收敛成了」、收尾三件套含求互动、正文有图序引用。

**感悟帖**——他听了/读了/想了点什么，把判断记下来。范文 `2026-08-03-podcast-chenmian.md`。特征：一条感悟一整段不拆（可以 100 字以上）、段内正常用句号、没有编号清单、没有互动句、结尾只裸写来源一行、零"我"零"你"（用"自己"）。

看不出是哪种就问他一句。两种都不是（比如纯经历叙事）就照最接近的那篇范文的呼吸走，并在交付时说明这是新体裁、库里没有存货。

## 总纲：范文优先

**范文教得会的，规则教不会。** 模仿一篇完整范文的呼吸，比遵守一百条风格规则更能让稿子像他——这一点在他的写作项目里做过对照实验，读范文写出来的稿子胜出。

所以起草阶段完整读 `references/examples/` 里**同体裁**的已发布笔记，凭手感写；清单留到写完当终审门跑。跨体裁的范文别混着读，两种节奏互相污染。

觉得成稿不像他的时候，回去再读一遍范文。这个判断几乎总是"范文读得不够"，而不是"规则写得不够"。

## 按需读取

每个文件在对应步骤读，用完即弃：

| 文件 | 什么时候读 |
|------|-----------|
| `references/examples/` 里同体裁那篇 | S3 起草前，读全文 |
| `references/voice.md` | S3 起草前对声音，S4 终审第三层 |
| `references/redlines.md` | S4 终审 |
| `references/cover-image.md` | S5 生封面 |

## S1 收料

料从作者身上来，AI 只做编排。他通常给：主题、几张截图、一段自己的想法。

先定体裁，再问料。**工具帖**看齐三样：

- **中心主张的实例**：这篇要说的那个好处，有没有一件真发生过的事撑着。只有结论没有实例就先问这个，别的都靠后
- **痛点起点**：为什么做这个东西，之前怎么难受的
- **落点动作**：用了之后他每天实际要做的事收敛成了哪两三步。这是签名句式「我要做的事情就收敛成了」的填空题

**感悟帖**只看齐一样：**每条判断有没有落到怎么做**。他给的往往是几条抽象结论，悬在那里读起来就是言之无物。缺的是他自己那句"这事具体怎么执行"，不是别人的案例——这一条的账见下面 S3。问法：这条判断落到你自己身上，具体要做什么／要警惕什么。

收完把料分两堆：**读者能拿走的**（同行也会碰到的问题、能直接用的判断、可以照做的动作）和**他的个人处境**（时间线、心路历程、私人纠结）。第一堆是正文主体，第二堆压成一句甚至删掉，判断标准见 voice.md 的"写给读者，不是写日记"。

缺什么问什么，一轮问 3 个以内。小红书篇幅小，问题多了他的回答量会超过成稿量。

他答不上来的地方，写"我还没试过，但想想就觉得 xxx"，比编一个"有一次我…"强。

配图逐张打开看清画的是什么。文件名和内容经常对不上，看过才知道哪张能配哪段。

## S2 定角度和标题

过一遍这个题成不成立：有没有让人想点开的钩子、看完能不能拿走点东西、同行会不会"对对对我也这样"。三占其二就能写，一条都不占就说清楚，换角度再来。

标题给 2-3 个候选，第一个按他的手迹来（见 voice.md 标题一节），其余换角度。20 字以内，前 10 个字放核心词。

体裁定不下来、或者定角度时有两种拍法（比如立判断还是讲经历），先问他再写。这一步替他做决定的代价是整篇重写。

## S3 起草

先完整读同体裁那篇范文，感受它怎么起头、怎么推进、怎么收尾，再读 voice.md 对一遍声音，然后直接写。

篇幅按 voice.md 手迹 12 的实测区间，写到 500 字以上回头砍。密度来自一句话一个判断，不来自堆料。

他自己动过笔的句子原样保留，包括笔误、语法不通、英文大小写不统一。那是随手记的质感，改通了就不像他了。

**别替他补别人的案例和数字。** 他说"言之无物"要的是他自己那句"这事具体怎么做"，不是去原文里搬战例。2026-08-03 那篇核了 11 条播客原文事实塞进正文（融资额、用户量、收入峰值、积压邮件数），他一条没留——别人的故事会把他的判断挤走，帖子从他的感悟变成一份摘要。想引外部事实先问他一句。这条收得回来（他删掉就是了），所以不在红线里，但它是这个 skill 到目前为止最贵的一次返工。

编不出来的细节标 `【需要你的真实经历：…】`，只放在非承重位。工具帖在正文里写上图序引用（图2）（图1/2），读者靠这个对图。

## S4 终审门

按 `references/redlines.md` 跑四层：事实审计 → 句式排查 → 声音校对 → 活人感。事实审计不过，后面三层不用跑，因为风格再像，事实是编的就整篇作废。

改完做一次回滚检查：信息密度掉了、句子长度变匀了、锋利判断被抹平了，就退回上一稿重修。改成白开水和留着 AI 味一样是失败。

## S5 封面图

先问他这篇要不要封面，再走 `references/cover-image.md` 的四步：**读完正文出 3 个封面方向 → 让他选 → 按选中的方向写生图 prompt → 交给 Codex 生成**。生图单次十分钟上下，别先跑了再问。

方向由这篇的内容现想，不套固定风格。他选完再写 prompt，prompt 写死之后 Codex 跑默认档就行，单次十分钟上下，放后台。

生不出来就把 prompt 存成 `封面.prompt.md` 留在笔记目录，明说"封面待生成"。占位说成已生成的话，他会拿着不存在的图去发布。

## S6 配图排序与图序对齐

按情绪曲线排：最能自解释的放前面，最炸的留到后面。封面 → 界面全貌 → 逐项细节 → 效果实拍。

排完回头核对正文的图序号。正文写着"（图2）追踪报告"而那张实际排在第 5 位时，读者就对不上。交付时把"正文图号 ↔ 实际第几张"列出来给他核一遍。

## S7 标签

先确认他这篇要不要标签。工具帖三层都打满，感悟帖他可能一个不打（2026-08-03 那篇线上就没有标签）。

要打的话 5-6 个，无空格分隔，覆盖三层：大词（#vibecoding #skill）+ 工具词（#codex #claudecode）+ 人群或活动词（#独立开发者 #vibecoding大赏）。

每个标签都要能在正文里找到对应内容。同一层级只留最具体的那个（"AI"和"AI工具推荐"留后者）。标签在发布时一次定好，已有流量的笔记改标签容易被限流。

## S8 交付与归档

先在会话里把四件产出物完整贴出来，正文用可直接复制的形态。

归档到 `内容/自媒体/小红书笔记/{YYYY-MM-DD} {主题}/`：

```
note.md          发布日期 / 链接 / 标题 / 正文全文 / 配图索引表 / 备注
最终配图/         00-封面.png + 01.png … 按实际上传顺序编号
图片/             封面 prompt、原始截图等工作文件
```

配图索引表三列：文件、内容、正文引用。线上顺序无法从本地反查时如实写明。

给他文件链接前，按工作区 CLAUDE.md 的规矩在 `_open/` 建 ASCII 短名 symlink。

## S9 发布后与迭代

链接回填进 note.md。

他手改过正文的话，diff 一遍找规律，然后分三种情况处理：**个案**（这一篇的特殊情况）保持 skill 不动；**普遍**（能在他已有笔记里验证）才回写 voice.md；**范文缺口**（这个场景库里没有存货）就把这篇成稿收进 examples/。

回写时优先做减法。只加不删的话这个文件会越来越长，长到模型开始漏读中间的内容，那时候再加规则只会让情况更糟。

## 红线

三条，共同点是发出去就收不回来：

1. **只写他真经历过的经历、数字、时间、心理活动。** 读者信任的是这些细节背后真有人经历过，编出来的质感是在透支他的账号信誉。素材外的细节走占位或诚实模糊
2. **效果按他说的写，用平实的词。** 他的读者是同行，"彻底改变""吊打"这类词一出现，整篇的可信度一起塌
3. **避开平台限流词**：震惊、必看、不看后悔，以及绝对化断言。判据是这个词有没有被用来给内容本身贴营销标签——"第一次用 Codex"、"最好先跑一遍"是正常叙述，"全网第一""效果最好"才是限流词。限流是平台侧动作，发了才知道，改不回来

风格层的约定（零 emoji、零加粗，以及分体裁的句号规则）在 voice.md，它们决定"像不像他"，和这三条"能不能发"是两件事。
