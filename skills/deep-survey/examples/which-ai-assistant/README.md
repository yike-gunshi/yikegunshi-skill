# 示范：普通人日常该用哪个 AI 助手

给 deep-survey 一个问题，得到一份调研报告：读完能做决定，每个关键说法都能点回原文。这是一次真实运行的完整记录，日期 2026-10-22。

## 给了什么

一个问题，原话如下（也存在 [input/课题.md](input/课题.md)）：

> 帮我深度调研一下：普通人日常该用哪个 AI 助手？比如 ChatGPT、豆包、DeepSeek、Kimi、通义千问、腾讯元宝、Claude、Gemini 这些，各自擅长什么、要不要钱、在国内好不好用，我该怎么选。

- **读者**：在国内、不懂技术、想挑一个 AI 助手日常用的普通人，用途是查资料、写东西、学习、办公。
- **要做的决定**：按自己的情况选一个，或选一个组合。

## 用户会怎么说这句话

在 Claude Code 里直接把这个问题说出来就行，「深度调研一下……」会触发这个 Skill。也可以点名调用：

```text
/deep-survey 帮我深度调研一下：普通人日常该用哪个 AI 助手？比如 ChatGPT、豆包、DeepSeek……我该怎么选。
```

## 代确认了哪些门禁

Skill 在几处需要用户拍板。这次是演示，由 AI 扮演用户作答：读者和决定照上面的设定，其余取 Skill 写明的默认值。

- **确认单**：读者和决定照课题原话。问题拆成：各自擅长什么、要不要钱、在国内好不好用（含对话数据怎么处理）、我该怎么选。演示时由 AI 按默认确认。
- **比较对象**：用户点名的产品超过了 Skill 一次比较的上限。处理办法是国产几款逐一比较；ChatGPT、Claude、Gemini 合为一组，组内仍分别列价格和可用性。演示时由 AI 按默认确认。
- **执行深度**：选默认的「聚焦调研」。问题边界清楚，不因为出现「深度调研」几个字就升级成完整专题。演示时由 AI 按默认确认。
- **范围边界**：只看个人版，站在中国大陆用户的角度，价格和功能按查证当天为准。不含开发者接入和企业版，也不提供绕过网络限制的方法。演示时由 AI 按默认确认。
- **检索预算用完之后**：Skill 规定此时要重新判断。仍有会影响结论的缺口，比如 ChatGPT 的价格和地区、国产付费档到底多给什么，于是选择定向补查，每项写明影响和停止点。补不到的写进报告的「还不知道的」。演示时由 AI 按默认确认。
- **图表**：Skill 允许零图。主笔判断几组对比用表格比用图清楚，所以没有出图。演示时由 AI 按默认确认。

## 和 Skill 默认做法不同的地方

这几处是因为产物要公开，不属于用户门禁：

- 产物写在本目录，不放在默认的调研根目录。
- 没有召回用户自有信息流。召回结果会把私人订阅的文章原文带进公开目录。
- 这次的网页访问经验没有写回共享信源库，只留在计划文件里。

## 得到了什么

**一份调研报告**：[output/普通人该用哪个AI助手.md](output/普通人该用哪个AI助手.md)。

- 标题就是结论：「国内日常用 AI 助手：免费国产款多半够用，按生态挑一个」。
- 开头一屏「一分钟看懂」先给答案，后面各章依次回答在国内能不能用、各自擅长什么、要不要钱、对话会不会被拿去训练，最后是按场景的选法和试用清单。
- 每个关键说法后面跟着可点击的编号，点开就是原文。会变的价格和条款注明了查证日期。没查到的单列在「还不知道的」，不拿估计填空。

报告由几个互相独立的角色接力完成：

1. 研究员采集证据。
2. 没参与采集的主笔读完全部材料，写成报告。
3. 没看过笔记的审读员冷读，提出意见。
4. 主笔按意见改一次。
5. 脚本统一来源编号，检查引用。
