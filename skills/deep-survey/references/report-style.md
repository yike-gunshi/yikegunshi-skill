# 报告文风

读者是从没接触过这个领域的聪明人。读完他要既懂这个行业怎么运转，又能做决定。参照晚点、36 氪智能涌现、a16z 的长文。

三个效果：**清晰易读、真实有用、适合传播**。下面每条规则都服务其中之一。

## 1. 分层阅读

篇幅跟着信息走，但必须能分层读：

| 层 | 读什么 | 用时 |
|---|---|---|
| 1 | 标题 + 一分钟看懂 | 1 分钟 |
| 2 | 判断句小标题 + 加粗结论句 + 图表 | 10 分钟 |
| 3 | 全文 | 30 分钟 |

写完自查：只读第 2 层，能不能讲完整个故事。不能，就是加粗句或图表没承担起结论。

## 2. 一分钟看懂

- 先一句话定义：它是什么、给谁用。外行连名字都没听过。
- 再一个反差：最多 2 个数字，并把「为什么反常」说出来。用「Google 带走创始人」制造反差，外行不知道这为什么是坏事。
- 再 5—7 条要点：每条 ≤45 字，最多 1—2 个数字，不带引用编号。最后两条是「带走的知识」：读者离开报告后还能用的规律或概念。
- 最后一行读法导航。
- 这里不追求信息密度，追求让人想读下去、并能马上复述。

## 3. 排版：短段落，结论在前

- 段落 ≤3 句、≤100 字，一段只讲一件事。
- 每个小节的形式：**加粗结论句** + 2—4 条证据要点。不写成一段论证。
- 并列 3 项以上用列表；3 个以上数字用表或图；用户声音用引语（`>`）。
- 每 400—600 字至少一个非文字元素（表、图、列表、引语）。
- 口径说明放图注或表下一行，不在句子里加括号。
- 小标题写成判断句：「模型已经不是门槛」，不写「技术分析」。
- 加粗只用在结论句和少数关键短语上。

## 4. 图文分工

判据是读者要对这块信息做什么：

| 读者要做的事 | 用什么 |
|---|---|
| 比较 3 个以上对象或数值 | 图或表 |
| 看形状：趋势、分布、集中度 | 图 |
| 看结构：流程、因果环、分层、位置 | 图，哪怕内容是观念 |
| 跟着推理走：有条件、有转折 | 文字 |
| 感受用户处境 | 引语 |

- 没有数据的地方不画数据图（会造出假精确），只画结构图。
- 数据图用 `scripts/make_chart.py` 从数据文件画，每个数值带来源编号。
- 图表主题按报告话题选一套，全报告统一：`make_chart.py --themes` 列出 11 套主题及适用话题（clean 干净信息图 / 杂志 / 瑞士三个家族）。拿不准时用 clean-默认。
- 结构图写 Mermaid 源文件，用 `scripts/render_visual.py mermaid` 渲染成 PNG（VS Code 默认预览不渲染 Mermaid）。
- 产品调研至少放 1—2 张产品截图，帮外行看见产品本身。官网常拦截自动截图，优先用应用商店页面；截图下一行写图注并带来源编号。
- 不用生图模型画任何带数字或文字的图。
- 图的标题也写成判断句。

常用图形：数据卡、横向条形、分组柱、折线、堆叠条（构成、一笔账）、单位图（比例直觉化）、对比矩阵（✓ / ✗）、流程图、因果环、分类时间线、定位图、价格权益表、引语、口径对照（宣传 vs 实测）、产品截图。

## 5. 密度不等于短

正文目标 8000—12000 字。密度是每句话的信息量：

- 每句至少带一个新东西：数字、名字、时间、因果、对比、原话。
- 一个事实只出现一次，后文引用写「见第四节」。
- 删掉过渡语和意义阐释：「值得注意的是」「综上所述」「这说明了……的重要性」。

## 6. 数字

- 每个关键数字配参照：和对手比（倍数）、和自己比（同比）、和上一代比（普通 App、SaaS）。
- 口径当场交代：官方披露直接写；第三方写「据 X 统计 / 估算」；推测写「推测」并给依据。
- 正文不出现【高】【中】【低】。
- 钱写成可复算的账：参数逐个列出、写明谁估的、按什么假设，算到结果。宣传口径和实测口径并列。

## 7. 竞品数据拆进正文

竞品档案（`40-dossier/*.csv`）按维度拆到对应章节：规模、收入、融资进第二节；口碑进第三节；价格权益进第四节；功能进第一或二节；合规进第六节的风险。数据不够一张表时，写成要点。附录只放一张总结表。

价格表后接 2—4 条价格分析：每美元买到什么、和参照产品比如何、付费墙设在哪里。

## 8. 分析：事实之后、结论之前

| 类型 | 做什么 |
|---|---|
| 归纳 | 跨案例找共同规律 |
| 对比归因 | 条件相近、结果不同，差在哪个变量 |
| 机制模型 | 画出生意的因果环，用它解释每家的选择 |
| 反直觉 | 指出常识错在哪 |
| 二阶推演 | 如果 X 发生会怎样 |

每条洞见：判断句标题 → 依据（见第 X 节）→ 推理 → 对读者意味着什么。和事实分开写，让读者分得清查到的和推出来的。

## 9. 案例

- 一个主线案例贯穿：按时间线讲，有人物、引语、转折点。
- 2—4 个对照，每个只证明一个变量。至少一个失败者、一个逆势成功者。

## 10. 结论

写成选项 + 适合谁 + 代价 + 先验证什么，再列会改变判断的信号。不写一句看好或看空。

## 引用与格式

- 编号紧跟被支撑的句子：`……拿走 89% 的收入 [1]`。
- 多个编号合进一个方括号，用英文逗号隔开：`[38,17]`。不要写成 `[38][17]`：两个方括号紧挨着，Typora 等编辑器会把它当成 Markdown 链接，只显示一个蓝色的「38」。
- 一句最多两个编号。
- 图片单独成段，图注另起一段写在下一行之后（中间空一行）；图和文字挤在同一段，部分编辑器会显示成空白。
- 表格格子写短语。
- 不写「本报告」「笔者」。
