# 报告文风

读者是从没接触过这个领域的聪明人。他要读完后既懂这个行业怎么运转，又能做决定。参照晚点、36 氪智能涌现、a16z 的长文写法。

## 密度不等于短

密度是每句话的信息量，不是总字数。正文目标 8000—12000 字，长度跟着信息走：机制要讲透，事实不要重复。v2 被否决的原因就是把"高密度"做成了"短"，删掉了用户动机、钱的账和案例。

- 每句至少带一个新东西：数字、名字、时间、因果、对比、原话。
- 一个事实只出现一次，后文引用写"见第四节"。
- 删掉过渡语和意义阐释："值得注意的是""综上所述""这说明了……的重要性"。

## 五个关键写法

1. **导语三段**：反常现象 → 核心结论 → 本文回答的问题。不从背景讲起。
2. **小标题写成判断句**："模型已经不是门槛"，而不是"技术分析"。
3. **讲机制，用新旧对比**：外行最缺坐标系。讲它和上一代产品哪里不一样，为什么这次能成立。
4. **钱写成可复算的账**：参数逐个列出，写明谁估的、按什么假设，算到结果。宣传口径和实测口径并列，主动戳破行业流行指标。
5. **结论写成选项 + 代价 + 反例 + 待观察信号**，不写一句看好或看空。

## 数字

- 每个关键数字配一个参照：和对手比（倍数）、和自己比（同比）、和上一代比（普通 App、SaaS）。孤立的"2000 万月活"外行判断不了大小。
- 口径当场交代：官方披露直接写；第三方写"据 X 统计 / 估算"；推测写"推测"并给依据半句。
- 正文不出现【高】【中】【低】。
- 数字贴着它支撑的话写。

## 案例

- 一个主线案例贯穿：按时间线讲，有人物、引语、转折点。
- 2—4 个对照案例，每个只证明一个变量。
- 至少写一个失败者和一个逆势成功者。

## 图

- 市场地图、时间线、钱的流向适合画图。用 Markdown 表格或 Mermaid（` ```mermaid ` 代码块，Obsidian 与 GitHub 都能渲染）。
- 图表标题也写成结论。

## 引用

- 编号紧跟被支撑的句子：`……拿走 89% 的收入 [1]`。一句最多两个编号。
- 常识性背景可不引。

## 格式

- 二级标题用模板的固定前缀（"导语""一、"…"八、""口径与来源"），前缀后的标题是判断句。
- 加粗只用在少数关键结论短语上，每节 ≤3 处。
- 表格格子写短语。
- 不写"本报告""笔者"。
