# 通用调研框架（四类之外）

对象不属于产品 / 行业 / 公司 / AI 工具时使用（如一项技术、一个政策、一个人物、一个事件）。本文件不预设维度，而是帮协调者和用户在 S2 一起定出 3—6 个维度。

## 定维度的方法

1. 从"要回答的问题"倒推：每个问题至少对应一个维度，每个维度至多服务两个问题。
2. 维度之间互斥、合起来能覆盖问题；不能回答任何问题的维度删掉。
3. 每个维度写一行：关键问题（2—4 个）、典型来源、预期查不到的东西。
4. 用 AskUserQuestion 把维度列表给用户确认（默认项放"按此维度"）。

## 常见对象的起手维度（供参考，不是模板）

| 对象 | 起手维度 |
|---|---|
| 一项技术 | 原理与边界 / 成熟度与采用者 / 替代方案对比 / 成本与风险 / 对我们的适用性 |
| 一项政策 | 原文要点 / 适用对象与时间 / 执行与案例 / 各方解读分歧 / 对我们的影响 |
| 一个人物 | 公开履历 / 代表作与观点 / 评价与争议 / 与我们的关联 |
| 一个事件 | 时间线 / 各方说法与证据 / 影响 / 后续待观察 |

## 置信度提醒

通用对象常依赖二方解读，"各方解读分歧"要并列呈现而不是取一方；推断类结论置信度低并写明推断链。

## 新增正式类型

某类对象反复出现时，把本次定下的维度整理成 `references/frameworks/<type>.md`（照 product.md 的表结构），并在 SKILL.md「按需读取」表加一行。只加文件，不改 SKILL.md 其他部分。
