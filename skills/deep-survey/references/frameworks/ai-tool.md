# AI 工具 / 开源项目类调研框架

适用：评估一个或多个 AI 工具、开源项目、skill、MCP、CLI 是否值得采用或集成。归纳自用户历史评估报告（乔木 Skill 评估、Agent-Reach 评估）：这类调研的核心是**相对自己技术栈的重叠度与集成判断**，不是功能罗列。

## 维度

| 维度 | 关键问题 | 典型来源 | 预期查不到 / 封顶"中" |
|---|---|---|---|
| 1 项目基本面 | Stars 与增速、创建 / 最后提交时间、语言、许可证、作者背景、issue 响应速度 | GitHub 仓库页与 API、作者主页 | 真实活跃用户数 |
| 2 能力与原理 | 做什么、怎么做（原理、依赖的上游）、输入输出格式、支持的平台 | README、源码目录、文档、作者文章 | 未文档化的边界 |
| 3 与现有栈重叠度 | 对照本机已有 skill / 工具逐项标"重叠 / 互补 / 独有"；替代谁、补谁 | 本机 `~/.claude/skills`、`Skill/` 清单（由协调者在确认单里给出） | — |
| 4 风险 | 凭证与 Cookie 要求、依赖链脆弱点、合规与封号风险、维护中断风险、提示注入面 | README、issues、源码中的认证逻辑 | 作者未来维护意愿 |
| 5 集成判断 | 立即 / 按需 / 不集成；具体接法、所需改动、验证方式 | 综合前四维度 | 多为推断，写明依据 |

## 默认问题集

1. 这个工具到底能做什么、靠什么做到？
2. 跟我已有的东西重不重叠，替代谁、补谁？
3. 有什么风险，值不值得集成，怎么接？

## 对比矩阵

多工具按五维做矩阵，第 5 维的格子写"立即 / 按需 / 不集成 + 一句理由"。单工具用维度事实表，并在第 1 维放"项目概览属性表"（Stars、创建、最后更新、语言、许可证、作者、定位）。

## 触发式模块

本类在对抗分析之后追加「集成判断」一节：三梯队（立即 / 按需 / 不集成）+ 每个工具的具体集成方案与验证步骤。

## 本类典型「存疑 / 待查」

实际运行效果（未实测）、Cookie 失效周期、作者维护意愿。写明"需本地实测或观察 N 周"。
