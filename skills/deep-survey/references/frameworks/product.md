# 产品类调研框架

适用：App、SaaS、硬件、消费品等单个或多个产品的调研。每个维度派一名研究员；对象 ≥4 个时可按对象而非维度分工，但笔记仍按维度归档。

## 维度

| 维度 | 关键问题 | 典型来源 | 预期查不到 / 封顶"中" |
|---|---|---|---|
| 1 定位与目标用户 | 解决谁的什么问题；官方口径与用户实际用法是否一致；主要替代方案是什么 | 官网、应用商店描述、融资稿、创始人访谈 | 真实用户画像分布（无一方数据） |
| 2 核心机制 | 产品靠什么机制留住人（功能、内容、关系、记忆、网络效应）；与同类的关键差异 | 产品实测、更新日志、技术博客、拆解文章 | 内部算法细节 |
| 3 商业化 | 怎么收费、价格梯度、付费点在哪；收入规模与结构；付费率 | 官网定价页、应用商店内购、财报 / 融资稿、Sensor Tower 等转述 | **收入、付费率：封顶中** |
| 4 增长与数据 | 用户量、增速、渠道；关键节点（上线、爆发、下滑）与原因 | 应用商店榜单、SimilarWeb / Sensor Tower 媒体转述、官方公布数字 | **流量、下载、月活：封顶中** |
| 5 用户口碑 | 被夸什么、被骂什么、最高频痛点；不同评分段说法是否不同 | 应用商店评论、Reddit、小红书 / 微博原帖、Product Hunt | 评论总体分布（只能抽样） |
| 6 团队与融资 | 创始团队背景、融资轮次与金额、投资方；团队规模与关键人物变动 | Crunchbase / 企查查转述、融资新闻、LinkedIn | 未公开轮次 |
| 7 用户与动机 | 用户是谁（带样本量的画像）、为什么来（动机分类与证据）、使用强度（时长、频次，配参照）、为什么走 | 学术研究、平台调查、Reddit / 小红书原帖、应用商店评论 | 动机占比（多为小样本） |
| 8 单位经济 | 每个用户带来多少收入、花多少成本（推理、获客）；能否写出一笔可复算的账 | 财报 / 招股书、公司技术博客、模型 API 定价页、行业访谈 | 单用户成本（多为推算） |
| 9 演进史 | 品类怎么走到今天：5—10 个关键节点及其意义；挑一家做主线案例 | 长篇报道（晚点、The Information、NYT）、维基、公司公告 | 早期内部决策 |


## 信息需求清单（S2 据此写 02-needs.json）

最低证据量是「够不够」的标准：没达到就定向补研，最多三轮。面向多个市场的消费产品，标「分市场」的需求每个市场各算一项（如 N5-中国、N5-海外）。

| 编号 | 模块 | 需求 | 分市场 | 最低证据量 | 优先来源 |
|---|---|---|---|---|---|
| N1 | 是什么 | 每家的官方定位与产品形态 | 否 | 每家 1 个一手来源 | 官网、应用商店描述 |
| N2 | 是什么 | 与上一代产品的机制差别、品类演进节点 | 否 | 3 源 / 2 族 | 长篇报道、维基、公司公告 |
| N3 | 是什么 | 产品截图（界面、核心功能） | 否 | 每家 1 张 | 应用商店页、官方博客配图 |
| N4 | 格局 | 品类规模与增速（下载、收入、用户） | 是 | 2 家统计机构，含最近一期 | Appfigures、Sensor Tower、a16z、QuestMobile、点点数据 |
| N5 | 格局 | 每家的用户规模，标口径与日期 | 是 | 每家 2 源 | 官方披露、招股书、第三方统计 |
| N6 | 用户 | 用户画像（年龄、性别、地区） | 是 | 2 份调查或平台披露，样本 ≥500 | 调查机构、学术研究、平台自述 |
| N7 | 用户 | 使用动机与使用强度（时长、频次），带参照 | 是 | 3 源 / 2 族 | 学术研究、调查、平台自述 |
| N8 | 用户 | 用户原声（好评、差评、流失原因） | 是 | 10 条原话（按条数计，min_findings）、5 源、3 个平台、近 12 个月 | 应用商店评论、Reddit、小红书、知乎、微博、B 站 |
| N9 | 钱 | 每家每档的价格与权益 | 否 | 每家全部档位 | 官网定价页、应用商店内购列表 |
| N10 | 钱 | 收入、付费率、每付费用户收入 | 否 | 每家 2 源（上市公司读原文） | 财报、招股书、第三方估算 |
| N11 | 钱 | 成本结构（推理、获客、毛利） | 否 | 3 源 / 2 族 | 财报、技术博客、模型 API 定价页 |
| N12 | 案例 | 主线公司的完整时间线与关键人物原话 | 否 | 6 源 / 3 族、3 段原话 | 晚点、The Information、NYT、访谈 |
| N13 | 风险 | 各市场的监管现状（标「已生效 / 待生效 / 征求意见」） | 是 | 每个法域读原文 | 政府网站、律所解读 |
| N14 | 风险 | 处罚、诉讼、下架事件 | 否 | 每起 2 源 | 权威媒体、法院与监管文件 |
| N15 | 竞品 | 每家的功能、融资与团队 | 否 | 每家 2 源 | 官网、融资新闻、数据库 |

## 默认问题集（用户只说"了解一下 X"时）

1. 这个产品现在做得怎么样（增长、商业化、口碑）？
2. 它靠什么留住用户，这个机制有多可复制？
3. 对我们意味着什么（进入 / 借鉴 / 回避）？

## 对比矩阵的列

默认用六个维度做列；对象 ≥4 个时把"用户口碑"拆成"最高频好评 / 最高频差评"两列，其余保持。

## 本类典型「存疑 / 待查」

付费率与 ARPU、分渠道增长、留存曲线、内部团队规模。写明"需一方数据或付费接口（如 AIsa 接 Sensor Tower）才能补"。
