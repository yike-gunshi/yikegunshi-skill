# 卡片写作规范

## 判据

卡片写成什么样由一条判据决定：**读者不读原文，只看卡片能不能复述这篇工作的机制、关键数字和适用边界**。读者是产品经理，不是研究员。

每写一块问一句：这段话读者能听懂吗，听懂之后他知道该拿它做什么吗。答不上来就是没写到位，与块数、顺序、标题措辞无关。

## 固定的部分

只有两样固定：

```
### 卡片标题（名称 + 一句话定位）

> 论文或资料：[完整标题](链接)，机构，YYYY-MM，配套资料链接
> 信息深度：拿不到全文时标注（摘要级、官方断言无实验数据等）
> 关联位置：引用它的正文章节或项目文档

![结构图](xxx.svg)

（正文，结构自定）
```

元信息引用块和结构图必须有：前者让读者判断该不该回原文求证，后者是卡片的可视化目录。

## 默认结构

多数资料适用以下五块，按需增删改名：

- **它回答什么问题**：研究之前大家卡在哪、通行做法的毛病，再写这篇验证的新路。读者先知道问题才能理解答案
- **怎么做的**：实验或系统设计。白话描述有画面感的做法，比如同一道题让模型生成多个回答，而非采用 GRPO 采样策略
- **发现了什么**：关键发现。每条自带结论、支撑数字、数字的读法。读法给外行一个判断标尺：这个数算高算低、和谁比、差距算不算大。反直觉的结论补一句为什么会这样
- **关键名词**：本篇涉及的术语，用类比和例子讲到位。跨篇复用的概念在首篇讲透，后续卡片写一句见某某卡片的解释
- **对当前工作的启示**：落到读者可执行的动作或可对标的数字，不写空泛感想

## 按内容调整结构

结构服务于理解，资料本身的形态决定它该长什么样：

- 综述、地图型文献：默认结构里的怎么做的意义不大，换成它把领域分成了哪几块、每块的代表工作是什么
- 数据集、benchmark：加一块数据集长什么样，给一两条真实样例，比抽象描述有效
- 官方文档、cookbook：正文多是建议清单，用建议加理由的形式承载；显式区分哪些有实验支撑、哪些是官方断言
- 方法有争议或有反例：单开一块讲边界与反例，比塞进发现了什么更醒目
- 一篇里有多个独立贡献：按贡献分块，每块内部再走问题、做法、结果的小循环

拆分和合并都可以，判据只有一条：这样排读者更容易读懂，还是更费劲。

## 写作约束

来自 pm-doc-write 通用约束，全部适用：

- 禁用装饰符号：角括号、弯引号、方头括号、长破折号、下划线强调。专有名词和字面串用行内 code
- 加粗只给指标名、数字、结论词，板块引导词加粗，不给整句加粗
- 不写翻案腔：不是 A 而是 B、看似 X 实则 Y 这类句式不用，判断从正面下
- 不写路标套话：以下是、综上所述、值得注意的是，都删掉直接说内容
- 数字带对比基线，孤立数字不落地
- 多点信息用 bullet 展示，不用分号串在一段里
- 教学类文档用完整句叙事，不压缩成名词短语

篇幅不设上限。讲清楚需要多少写多少，讲不清楚才是问题。

## 类型决定重心

| 输入类型 | 卡片重心 | 配图重心 |
|---|---|---|
| 方法论文 | 机制怎么运转、消融实验每一刀的含义 | 流程闭环 + 消融结果 |
| 工程实践、基准 | 结构怎么搭、可对标的数字 | 分层结构 + 数字对标 |
| 官方文档、博客 | 官方口径的建议清单、断言与实证的区分 | 建议结构 + 使用流程 |
| 综述 | 领域怎么分块、各块代表工作 | 领域地图 |

## 范例

以下节选自 RaR 卡片定稿，学它的深度和口吻，别照搬结构：

**它回答什么问题**（看怎么把问题背景讲到读者能理解）

> 数学和代码任务能自动判对错，答案对就给奖励，强化学习的主要进展都建立在这类可验证奖励上。医疗咨询、开放问答没有唯一标准答案，此前通行做法是训一个 reward model 或让裁判模型直接打总分，两者有同样的毛病：分数是黑盒，看不出好在哪差在哪，还容易被更长的回答、更讨好的语气骗分。这篇论文验证一条新路：给每道题写一份 rubric，逐条判定后聚合成分数，直接当强化学习的奖励用。

**发现了什么**（看结论加数字加读法的写法）

> - 主结果：rubric 奖励比总分奖励在 HealthBench 上最高相对提升 31%，GPQA-Diamond 上提升 7%，训练波动也更小。读法：31% 是相对值，即基线分乘 1.31；医疗这类主观域提升大，科学选择题这类偏客观域提升小，rubric 的价值集中在没有标准答案的地方

**关键名词**（看类比的用法）

> - 消融实验：把系统里某个部件单独拆掉再测效果，看这个部件到底贡献多少。类比：怀疑汤里某味调料多余，就做一锅不放它的汤对比
