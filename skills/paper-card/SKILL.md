# paper-card — 论文与最佳实践的学习卡片

像一个替用户精读论文的研究伙伴。交付标准只有一条：读者不读原文，只看卡片就能复述这篇工作的机制、关键数字和适用边界。读者是产品经理，不是研究员——所有术语都要落到白话和类比，所有数字都要带读法。

## 输入与核实

输入可能是 arXiv 链接、PDF、官方文档页、博客 URL，也可能是用户贴的一段资料描述。动笔前先核实三类信息：

- 标题、机构、发布时间：以 arXiv 或期刊页面为准。摘要页不显示机构时抓 HTML 全文页的作者栏；仍拿不到就填一个减号占位，不猜
- 关键数字：只写抓取到或用户提供的，每个数字能指出来源位置。编出来的数字一旦进了学习资产，之后会被当真引用
- 拿不到全文时（付费墙、页面渲染失败），用搜索找摘要级信息兜底，并在卡片元信息里写明信息深度是摘要级——深度如实标注，读者才知道该不该回原文求证

## 流程

1. 认输入类型：方法论文、工程实践或基准、官方文档或博客。类型决定卡片和配图的重心（详见 card-template）
2. 抓取并核实：WebFetch 摘要页与 HTML 页；官方文档抓正文；失败走搜索兜底
3. 写卡片：读 `references/card-template.md`。判据是读者不读原文也能复述这篇工作，结构按资料形态自定，不套固定块数
4. 画结构图：读 `references/svg-guide.md`，按分层底板卡片风画 SVG
5. 渲染自查：用无头浏览器把 SVG 截图后亲眼看一遍，检查文字溢出卡片、箭头错位、布局重叠。命令在 svg-guide 里
6. 交付：默认产出本地 markdown（卡片正文 + 内嵌 SVG 图），文件中文命名，交用户确认。用户要发飞书时，SVG 转画板插入，正文按飞书格式写入

## 启示板块的对象

对当前工作的启示这一块，从会话和项目上下文里取用户当前在做的事（例如某个评测项目、某条业务线）。上下文里取不到时，问一句用户想关联到什么工作，别写成放之四海皆准的空话——启示的价值在于具体。

## 批量场景

一次处理多篇时，逐篇走完流程再进下一篇，每篇渲染自查通过才算完成。分批交付，别攒到最后一起交——前几张的反馈能修正后面的写法。

## 红线

1. 数字、机构、时间只写核实过的。核实不到就占位或标注，不编造——错误数据进入学习资产后会被反复引用，纠正成本远高于当场留白
2. 拿不到全文时必须在卡片里标注信息深度，不把摘要级信息包装成精读结论

## 输出骨架

卡片的写作判据、默认结构与调整原则在 `references/card-template.md`，SVG 布局规范和自查命令在 `references/svg-guide.md`。写卡片前读前者，画图前读后者。

固定的只有两样：元信息引用块和结构图。元信息让读者判断该不该回原文求证，结构图是卡片的可视化目录。正文怎么分块由资料形态决定。
