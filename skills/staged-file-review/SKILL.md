# 文件暂存审阅

让用户决定哪些建议进入原文件。准备阶段只写暂存区；HTML 中的标注记录意见，实际写回在收到明确执行指令后单独进行。

## 先沿用已有决定

从会话确认目标文件、希望达到的结果和已有审阅意见。已经讨论过的布局、原文来源、结论粒度不重复询问。默认使用本包的左右对照页面，用户要求先讨论页面时先讨论。

创建这个 Skill 的授权、创建审阅页的授权、认可某个视觉布局，都不等于批准应用候选文件。用户说“标注完了，按标记修改”则已经授权相应执行，不再逐文件询问。

## 1. 建立暂存区

选一个本地持久目录承载本批次材料，放在用户指定位置或项目现有审阅附件目录。不要放进待修改的源文件目录内部，也不要把用户文件内容存入本技能包。非公开材料保持本地，不上传托管、不提交 Git。

使用 [scripts/review.py](scripts/review.py)，运行时把 `SKILL_DIR` 换成本 Skill 的真实安装路径：

```sh
python3 "$SKILL_DIR/scripts/review.py" init /absolute/review-session \
  --files /absolute/project/AGENTS.md /absolute/project/CLAUDE.md \
  --title "项目规则修改审阅"
```

输入是现有的 UTF-8 文本文件。符号链接会定位到真实文件，同一真实文件只纳入一次。新建、删除、重命名文件及二进制产物不套用文本替换，由主任务另行形成可审阅方案。

生成：

- `before/`：初始化时原文件的逐字节快照，包含用户已有的未提交内容。
- `after/`：供模型编辑的候选副本，名称与 `manifest.json` 中的文件编号对应。
- `manifest.json`：源路径、校验值及展示信息。

只编辑 `after/`。在清单里补充每份候选的 `reason`（为什么改）、`risk`（可能失去的约束或代价），可调整 `label`、`detail`、`group`。不要改源路径、编号、权限或原文校验值，不改 `before/`。

如果发现原文件已经被本次工作提前修改，先寻找真实的修改前备份或已核实的差异。不要把修改后的内容伪装成“原文”，也不要用 Git HEAD 覆盖用户已有改动。没有可靠基线时说明缺口；需要恢复原文件时遵从该恢复动作的实际授权。

## 2. 生成并检查 HTML

```sh
python3 "$SKILL_DIR/scripts/review.py" build /absolute/review-session
```

此步骤会检查源文件是否仍与初始化快照一致，然后生成 `index.html` 和冻结的 `review.json`。无变化的文件不进入审阅清单。页面模板见 [assets/review.html](assets/review.html)，通常直接复用，不重新设计整套页面。

页面包括全文左右对照、行号、差异跳转、搜索、未变内容折叠、字号、文件级意图与代价、逐处结论和备注、整份处理与撤销、浏览器保存、导出/导入意见。所有修改默认待审阅。文件内容按纯文本展示，不执行其中的 HTML 或脚本。

用真实浏览器检查至少一个文件的完整对照和意见导出，提供可点击的本地 HTML。单文件离线可用；如需预览服务，仅绑定本机地址并核对实际返回的端口。

生成后不覆盖 `review.json`、`index.html` 或本批次的前后版本；改候选就创建新批次，让旧标记继续对应旧版本。导出的意见绑定批次编号与两个版本的校验值。

## 3. 等待人工结论

| 标记 | 含义 |
|---|---|
| 接受修改 | 可以纳入随后明确授权的应用 |
| 保留原文 | 该处不应用 |
| 待审阅 / 未标记 | 该处不应用 |
| 需要调整 | 当前候选不应用；根据备注另做候选，重新提供审阅 |

有备注但仍是待审阅，不算接受。不要为了排版、引用一致或“更合理”顺手应用相邻未标记内容；部分接受造成组合不完整时，展示具体冲突并暂缓该文件，独立文件可以继续。

用户意见保存在他们实际使用的浏览器中。优先读取用户给的导出 JSON；如果浏览器可用，可在对应审阅页点击“导出意见”取得文件，不修改用户标记。不要从新开的空白浏览器或旧测试数据推断用户意见，也不扫描浏览器私有数据库。无法访问结果时，让用户提供导出的 JSON。

## 4. 只应用已批准的部分

先预览应用计划，这个命令不写源文件：

```sh
python3 "$SKILL_DIR/scripts/review.py" apply /absolute/review-session \
  --decisions /absolute/文件审阅意见.json
```

核对已接受数量、未标记数量、需调整备注和发生变化的源文件。`apply` 的输出是对象和行段对应的计划；实际候选文本在冻结的 `review.json`。必要时检查部分组合后的语法或规则逻辑，不扩大修改范围。

只有会话中已有明确写回指令时执行：

```sh
python3 "$SKILL_DIR/scripts/review.py" apply /absolute/review-session \
  --decisions /absolute/文件审阅意见.json \
  --execute --authorization "用户要求：标注完了，按我标记的内容修改，未标记的不修改"
```

`--authorization` 记录用户实际指令，不能用自己编写的批准替代用户意见。一次批准覆盖对应批次中已接受的部分，无需重复确认。

脚本从原文按连续差异块重建目标，只替换状态为 `accept` 的块；其余保留原文。保留未选择行段的原始换行符和文件末尾换行状态。每份文件写入前核对内容、路径和权限，用单文件原子替换并读回验证。

源文件变化、符号链接转向或权限变化时不覆盖该文件，报告具体冲突；已批准且没有冲突的文件可以继续。重复应用同一结果会识别已完成，不重复写入。这个检查不能代替与其他写入任务协调；不要同时运行两个应用进程。

`receipts/` 保存实际意见、用户执行指令、逐文件结果及校验值。退出码 `2` 表示有文件阻塞，不能当成全部成功；“需要调整”单列为未应用。应用后若要改变旧选择，基于当前源文件开新批次，不用旧原文覆盖已完成的其他工作。

## 验证与交付

报告已应用、保留、待调整和阻塞的数量，并链接实际回执。源文件未发生变化的准备阶段不能称为“已修改”。不自动提交、推送、合并或部署。

维护本技能的脚本时运行 [scripts/test_review.py](scripts/test_review.py)：

```sh
python3 "$SKILL_DIR/scripts/test_review.py"
```

这些测试验证暂存、选择性应用、原文保护和错误边界；通过不代表真实模型的自动触发率或任务成功率提高。
