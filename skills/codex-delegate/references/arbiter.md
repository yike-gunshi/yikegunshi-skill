# 盲解仲裁

用于有争议、判错代价高的结论：bugfix 根因有两种都说得通的解释，架构选型说不清哪个更好，或者用户说「有争议」「second opinion」「盲解一遍」。

它和对抗式审查不同：审查是拿着一个已有方案去找漏洞；仲裁是让两个解题者**互不知情地**各自解同一道题，再对比结论。两份答案一致才有说服力，前提是它们真的独立。

## 步骤

1. **先封存 Claude 的答案**。在派题之前，把 Claude 自己的结论和理由写进 `<worktree>/.forge/jobs/<label>.claude-answer.md`。先写下来，才能防止看到 Codex 的答案后不自觉地修正自己。
2. **写题面**：`<label>.question.md`，只包含问题本身和中立的证据（日志、复现步骤、相关文件路径），要求给出结论、依据和置信度。
3. **派给 Codex**：`D submit --read-only --label <label>-arbiter --prompt-file <题面>`。仲裁只判断不改代码。
4. **对比**：
   - 一致：采纳，在小结里注明「双方独立得出」。
   - 不一致：Claude 裁定。逐条对比双方依据，能用一个便宜实验分出对错的，先跑实验再定。小结里写清分歧点和裁定理由。

## 污染规则

题面里不能出现任何一方的答案、结论或倾向。「我怀疑是连接池污染，请验证」已经被污染了，它会把 Codex 引向确认，得出的「一致」是假的。

发现题面被污染了（包括证据挑选得明显偏向一方），就重写题面、重派，不要在原作业上打补丁：Codex 已经看过的东西收不回来。

同理，不要用 `resume` 去追问仲裁作业「你确定吗，有没有可能是 X」，那等于把答案告诉它。要补充证据就开一个新的仲裁作业。
