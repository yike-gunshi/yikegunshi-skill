# 来源接入与生产只读采集

目录：来源登记 → 内置采集器 → 本地 → GitHub → 飞书 → 部署与生产 → 失败与时间。

## 来源登记与工具边界

先识别项目明确关联的仓库、文档目录、部署环境和已有导出，读取当前宿主提供的工具说明及必要来源 Skill。核对调用参数、分页方式、返回字段和权限后执行。可以利用用户已确认的授权，不因为阶段推进重复确认。

来源范围与本次议题分别管理。每个来源登记：稳定 id、类型、定位、对象/子树范围、历史范围、评论与附件范围、读取方式。能访问某个账号不等于账号内所有空间都属于项目；不跨项目顺手收集，不根据文章的参考架构自行部署 MCP 或连接生产系统。

只有以下事实足以标记一个来源完整：范围明确、所需对象与嵌套页枚举完、正文与附件取得、失败项已处理或按约定明确排除、当前权限已核对。仅“导出命令成功”不够。

调用中仅使用所需只读字段及操作。正文、版本、来源定位、时间、环境、页信息用于材料和证据；认证令牌、无关用户资料、修改权限、消息发送能力不使用。缺工具、缺权限或账号不可用时保留旧快照、记缺口，并继续独立的本地整理。

## 内置采集器的实际范围

来源样例仅用于填写，不代表这些项目或端点存在，也不构成授权。选择实际需要的条目，替换占位信息后合入 init 的 `config.json`，重新 scan。

```bash
"$CONTEXT_PYTHON" "$CONTEXT_SKILL/scripts/collect_source.py" --state "$CONTEXT_STATE" --source "$SOURCE_ID" --output "$CONTEXT_STATE/incoming/source.json"
"$CONTEXT_PYTHON" "$CONTEXT_SKILL/scripts/context.py" ingest --state "$CONTEXT_STATE" --input "$CONTEXT_STATE/incoming/source.json"
```

| 类型 | 确认的字段与调用 | 当前边界 |
|---|---|---|
| `kind: github` | `scope.repo` 为 owner/repo；`scope.include` 取 `issues/pulls/releases/deployments`；可选 hostname；通过 gh 逐页 GET | Issue 评论、PR 讨论/评审/变更/提交、部署状态分别枚举；发布附件、缺失 patch 等需宿主补取 |
| `kind: lark` | `scope.documents` 为明确文档 URL/token 数组，不带章节锚点；调用 lark-cli full XML JSON | 不自动遍历 wiki；默认评论在范围内，文档抓取未取得评论则 partial；用户明确排除评论后才设 `scope.comments: false`；嵌入媒体/表格/引用需补 |
| `kind: production, transport: http-json` | 已约定的 HTTPS GET JSON 端点，显式字段、固定时区区间、分页与预算 | 不内置数据库/SSH 连接，不跟随 HTTP 重定向，不支持未知接口自动适配；其他只读查询通过宿主工具导入 |

HTTP JSON 额外字段：

- `request.url` 为具体批准的 HTTPS 端点；`start_param/end_param` 把 window.start/end 传给服务；`timestamp_field` 取每条记录的时间字段。边界为 start 包含、end 不包含，结果超出范围会失败。
- `request.id_field` 可指定稳定唯一记录键；id 和时间字段也在 `fields` 内。省略 id 时用已选字段的内容指纹，重复记录会报缺口，不能据此丢记录。
- `request.fields_param` 将已批准 fields 作为逗号分隔参数传给端点；若端点固定只返回批准字段，实际核验后可用 `fixed_response_fields: true`。字段投影只保留许可字段进入缓存，不能代替读取范围授权。
- `request.params` 为额外已批准筛选条件；`headers_env` 将请求头名映射到凭证环境变量名。环境变量内包含完整头值，令牌本身不进入配置、命令或产物。
- `pagination.items_path` 指向记录数组；`next_cursor_path/cursor_param` 对应返回游标与下页参数，末页应为 null 或空字符串。确定不分页时设 `single_page: true`，不能为跳过后续页随意使用。
- `budget.max_requests` 是同一轮累计请求上限，失败请求也计数；`timeout_seconds` 为单次超时，`max_response_bytes` 为单次返回字节上限。按配置核对实际数值，不盲用样例。

`window` 在内置 HTTP 采集器中需要固定 ISO 起止时间并含时区。若项目约定滚动窗口，由宿主先按已确认规则计算并记录本轮实际区间，再在 scan 前更新配置；改变规则仍需按原授权边界处理。HTTP 字段路径使用点分隔对象路径，不假定支持任意查询表达式。

`--resume` 仅复用同一轮次与来源配置的成功响应，累计预算不清零。先检查分页与源版本是否仍可续读；动态列表已变化时重新采集并记录时间偏差。达到本轮上限后停留 partial，不通过不断新建轮次绕过预算。

## 本地项目

收录当前工作区实际文件，区分 HEAD、暂存、未暂存、未跟踪与忽略状态；有 Git 时保存分支和提交，无 Git 时保存目录身份与内容快照。工作区代码、已合并代码和生产代码分别解释。

以文件清单检查正文、测试、配置、迁移、脚本、文档、设计资源和项目导出。项目内符号链接或子模块先确定指向及归属，不默认追到根目录外。依赖副本、构建产物与缓存可按明确分类排除，其版本、用途及定制改动仍需保留。

`.env`、密钥、证书、数据库备份等先按安全边界分类；需要解释的配置名称、类型、默认值保留，凭证值以脱敏标记替换。不要先全量复制敏感原文再期望 build 清除缓存。

同一文件采集后又变化时核对指纹、重取正文并复核说明。自有状态与导出排除出源扫描，以免递归收录。

## GitHub Issue、PR 与发布演化

使用现有 GitHub 只读工具或已认证的 `gh api --method GET`。逐接口核对官方或工具 schema，再构造实际端点；`--paginate` 可取得分页，`--slurp` 可保留页边界，但每个嵌套列表仍需独立取完。

正文与状态之外，按范围取得 Issue 评论、PR 评论与评审、变更/提交关联、发布和部署记录。保留对象号、作者归属所需信息、创建/修改时间、状态、源链接和版本；不能以“最近 100 条”替代约定全历史。

PR 中的提议、评审意见、合并结果和上线结果是不同事实。保留讨论全文，通过关联说明解释最终决策；没有明确结论时写未知。日志里的部署 SHA 优先与对应提交关联，不能默认等于当前 HEAD。

权限或限流失败保留已经取得的页和剩余游标，来源标 partial。新增/更新事件不覆盖删除信息时做完整清单对账；权限范围变化时不据此判删除。

## 飞书文档、子树、表格和附件

可使用宿主飞书只读工具、已配置的 `lark-cli` 或 `lark-export`。使用导出 Skill 时先读取其 SKILL.md，遵循其实际能力；CLI 先查当前 schema。对已确认支持的文档，读取 full scope、full detail 的正文，例如契约中的 `docs +fetch --scope full --detail full --doc-format xml`，补齐当前 CLI 要求的文档参数。不要猜凭证或假定只取 outline 已得到全文。

采集顺序：

1. 保存登记的根节点/文档清单与子树范围，遍历所有页和子节点；记录无法进入的节点。
2. 保存文档正文和结构，包含列表、代码块、表格、嵌套块、嵌入对象及纳入范围的评论；检查 API 是否只返回外链或截断块。
3. 按正文引用取得图片和附件，保留原始对象标识、文件名及其所属段落/文档。文档里只有图片 token、远程 URL 或本机路径时仍有交付缺口。
4. 对照正文引用集合、下载成功集合和本地附件集合，找缺失引用、未关联的孤儿附件和重复对象。孤儿不能静默丢弃：查明归属、纳入适当材料或明确解释排除理由。
5. 用节点清单和转换结果核对页面/块/附件，检查未支持格式和失败项后才标完整。权限页、空壳 Markdown 或导出 0 字节不是成功。

表格需保留完整结构、工作表范围、公式/值含义及实际可获取的精度，图片需附件与文字解释并存。无法解析不等于没有内容：保留已授权附件，列语义解析缺口。

内置文档采集器若仅支持显式文档列表，不要声称已遍历整个 wiki；通过宿主工具补齐列表、嵌套对象和媒体后，再组织完整 envelope。用户已有导出同样登记其源范围、导出时间和未完成项。

## 部署记录与生产数据

部署记录按明确环境/服务收录发布、回滚、目标版本、时间和现有验证证据；一次启动成功不能证明业务正确。访问部署记录的授权不自动包含全库、生产 SSH 或完整客户日志。

生产首次配置记录以下实际约定：

| 项目 | 配置需要说明的内容 |
|---|---|
| `scope` | 哪个环境、服务/库/表/视图或读取端点，允许的查询对象和模板 |
| `fields` | 允许读取的字段、输出粒度和必要过滤，不含未授权个人信息 |
| `window` | 固定区间或滚动规则、时区；历史无界不是默认值 |
| `budget` | 请求/行数/数据量、耗时、分页、并发和速率的实际限制 |
| `read_only` | 受限账号、只读事务或受限 GET API 等机制及实际核验 |
| `approval` | 用户已确认的来源范围与时间记录，不从可用凭证推断授权 |

凭证只保存环境变量名或已有凭证服务引用，不写明文。模板中的确认标志为 false；只有真实约定及核验后更新 `approval.confirmed`、实际 `confirmed_at` 和 `read_only.verified/mechanism`。数据库只看 SQL 以 SELECT 开头不能证明只读，语句、函数与事务权限共同检查。

脚本未内置的数据库、SSH 或监控适配由宿主现有只读工具完成：执行已确认查询，保存脱敏全文与附件及采集元信息，转换为 envelope 再 ingest。没有现成访问方式时报告缺口，不建立新隧道、开放端口、安装远端 Agent 或申请更大数据权限来凑完整。

GET 也需确认端点为只读及数据范围受限。尽量在源端选择允许字段与时间区间；如果接口不能限制返回内容，先确认实际响应是否仍在授权范围，不能仅靠事后导出时裁列绕过读取边界。

查询返回逐行数据时保留约定范围内全部记录；约定的是聚合指标时保存查询定义、单位、维度、粒度及精度。汇总结果不能称为原始日志全量。现成报表/导出与直接采集同时收录，分别标来源、区间和重复/差异关系。

预算耗尽后按配置允许方式接续；总预算不能被反复分批绕开。无法在预算内完成时标出剩余页/区间，等待下一次获准的运行或用户调整范围，不把前 N 行/采样称完整。

## 失败、恢复与时间一致性

每次采集记录开始/结束时间、源版本、环境、实际覆盖区间与剩余游标。每轮有目标截止时间；来源支持历史截止读取时对齐，不支持时写明时间差。不要把不同部署期间的数据拼成一个不存在的当前状态。

来源缺失、权限撤销、请求失败、明确删除分别记录。只有可靠删除事件或权限/范围未变时的完整对账才能删旧材料。外部失败使旧材料过期，不使其自动消失。

恢复前验证游标与源版本仍有效；不可靠时重读该来源。更新字段、时间或查询对象超出既有范围时先说明新增边界，继续已授权的独立部分。保存时间与版本并不能证明解释正确，最终仍需核对证据与结论。
