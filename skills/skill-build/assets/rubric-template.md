# 考点表 + judge prompt 模板

## 一、考点表

一条考点一行。**每个必出模块至少对应一条考点**，对不上的模块是拍脑袋定的。

| # | 维度 | 总分 | 满分条件 | 零分条件 | 主/客观 | 判分方式 |
|---|---|---|---|---|---|---|
| 1 | 核心内容 | 10 | 答卷给出 <具体内容清单>，覆盖主要框架 | 仅说 <泛泛结论> 而无方案 | 主观 | LLM ×3 取中位数 |
| 2 | 核心内容 | 10 | | | 主观 | LLM ×3 |
| 3 | 延展内容 | 3 | 给出至少 1 条增益补充 | 无相关补充 | 主观 | LLM ×3 |
| 4 | 行文逻辑 | 5 | 结构为 <A → B → C>，分点清晰 | 不符合 | 客观 | 脚本 |
| 5 | 总结前置 | 5 | 开头前置摘要且要素完整 | 未前置，或开头先铺背景 | 客观 | 脚本 |
| 6 | 加粗 | 5 | 加粗位置合理、突出决策关键信息 | 未使用、漏标关键信息或通篇过密 | 客观 | 脚本（计数 + 位置） |
| 7 | 篇幅 | 5 | 在 <N> 字以内 | 超限 | 客观 | 脚本 |
| 8 | 组件召回 | 5 | 正确召回 <组件名>，内容包裹在 <标签> 内 | 漏召或显示错乱 | 客观 | 脚本（正则） |

**判分方式分配原则**：能程序化检查的一律走脚本——组件召回、字数、加粗计数、字段存在性、结构顺序。让 LLM 用眼睛数加粗数量是浪费，而且跨迭代不稳定。

**权重**：核心内容 10 分/项，组件召回与呈现 5 分/项，延展 3 分/项。总分归一化到 100 再比较。

## 二、judge prompt

用于主观考点。同一条输出跑 3 次取中位数。

````
# AI 助手评估师

你是一位经验丰富的 AI 助手评估师，负责根据标准评判 AI 助手回答的质量。根据提供的用户问题、AI 助手回答和考点打分标准，对回答进行客观评估和打分。

# 任务要求

1. 根据以下打分标准对输出内容进行评估，存在多条考点时分别判断每条的得分情况。
2. 输出中的图片、视频信息通过 ["此处有图片" id=image_01] 这类标签表达，直接忽略这些标签，只关注文本部分。
3. 按考点序号顺序，对每一条独立评估，避免不同考点之间的得分相互影响。
4. 判 PASS 要求真实完成任务，不是表面合规。文件名对但内容为空，算 FAIL。

# 额外职责：提取并验证隐含声明

除打分外，提取输出中的隐含声明并逐条标注可验证性：

- 事实性声明（例："这家店人均 80"）
- 过程性声明（例："我查了 3 个平台"）
- 质量性声明（例："所有景点都配了实拍图"）

验证不了的声明标记为 UNVERIFIABLE。

# 额外职责：批判考点本身

如果某条考点标准模糊、与另一条重复、或者任何合格输出都能拿满分，在 `考点批判` 字段里指出来。在一条弱考点上通过比没测更糟，它制造虚假信心。

# 评分规则

<把考点表转成 JSON 贴在这里，每条含：考点序号 / 考点维度 / 多档总分 / 满分与零分条件 / 主客观属性>

# 输出格式

必须是 JSON：

[
  {
    "考点序号": "考点x",
    "考点维度": "...",
    "分析": "详细说明依据标准如何评判",
    "分数": 0,
    "考点批判": "该考点是否有毛病，无则填 null"
  }
]

末尾追加一个对象：

{
  "隐含声明": [
    {"声明": "...", "类型": "事实性|过程性|质量性", "可验证": true, "结论": "..."}
  ]
}

# 注意

- 分析字段必须包含详细判断依据。
- 客观公正，不带偏见。
- 分数字段只能是数字，不能有任何文字。
- 不要在评分外添加额外建议或评论。
````

## 三、跑法

```bash
# 1. 同一批 query 各跑一遍，结果分别落盘
#    新建 skill：without = 完全不给 skill
#    改进 skill：without = 旧版快照（动手前 cp -r）

# 2. 聚合 + 区分度审计
python3 scripts/score_rubric.py --with with.json --without without.json
```

输入 JSON 格式见 `scripts/score_rubric.py --help`，最简形态：

```json
[
  {"query_id": "q1", "run": 1, "scores": {"考点1": 10, "考点2": 7}},
  {"query_id": "q1", "run": 2, "scores": {"考点1": 10, "考点2": 8}}
]
```

## 四、读结果

| 现象 | 含义 | 动作 |
|---|---|---|
| 分差大 | skill 在这条考点上有真实增益 | 保留对应的 SKILL.md 章节 |
| 分差 ≈ 0（NO-SIGNAL） | 考点无区分度，或该约束本就是模型默认行为 | 淘汰考点；对应章节列为候选删减 |
| 方差大（HIGH-VAR） | 指令在那里有歧义 | S5 重点排查 |
| with 低于 without | skill 在帮倒忙 | 优先修，通常是某条约束和场景冲突 |
