## 先归因，再动手

v1 评测后，逐条看了失分和盲评输掉的几组，按 skill-build 的三分法归因：

| 现象 | 归因 | 处理 |
|---|---|---|
| 多数考点（结论召回、待办召回、负责人、没谈拢、骨架、疑点标注）两组都满分 | 考点的问题，也说明这些约束本来就是模型的默认行为 | 考点列为淘汰对象；对应的 SKILL.md 段落列为候选删减，本轮删了"回扫查漏"一步 |
| 用 Skill 一组一次在结论里补了会上没说的适用范围（"白天夜间统一适用"）；不用 Skill 一组也出现过同类问题（"即日起作为标准执行"） | Skill 指令的问题：只说了"没拍板的不进结论"，没说"拍板了的也只写说定的那部分" | 在"判结论还是没谈拢"里加一句通用规则，例子换成和评测题无关的 |
| 盲评评委几次偏好表格 | 不改。列表是访谈里按默认确认的；但 SKILL.md 给的理由"群聊里表格常常显示不出来"是没核实过的说法 | 改写理由，不再断言某个平台的显示效果 |
| T1 里"让行政去统计"，Skill 标成负责人待定，评委认为已交给行政 | 考点（评委）的问题：评委不知道场景设定里"待办必须有负责人"，部门不算具体负责人 | 不改 Skill |
| 盲评评委按"今天是 10/22"说截止已过期 | 评委的问题：纪要本该会后当场发 | 读结果时扣除 |
| "会后需确认"的触发条件在骨架、输出说明、失败处理里写了三遍 | Skill 指令的问题：重复 | 删掉输出说明里那一遍，骨架标题里注明"命中才出" |

## 停在这里

v2 和 v1 的分差在噪声范围内，按 skill-build 的停止条件"不再有实质进展"，停下发布，不继续在这五道题上打磨——再改下去就是对着这几份转写稿过拟合。

## 下一步（按价值排）

1. **换真实的、更长的转写稿重测。** 现在的转写稿是 AI 写的几分钟短会，陷阱也是自己埋的。真实的一小时会议跑题更多、结论更散，"把没定的写成定了"可能更常见，也可能出现这次没测到的失败。用脱敏后的真实会议补一批题，再判这个 Skill 值多少。
2. **把评测预算集中到有区分度的地方。** 淘汰两组都满分的考点，多造"有条件的暂定""要请示会外的人""提议了没人表态""会上补了一句适用范围"这类题，并让评委把"写成定了"和"编造"分开判清楚（抽检发现评委会放错格子）。
3. **星期几别让模型算。** v2 有一次把日期的星期写错了。要么骨架里的日期只写到日，转写稿写了星期才写；要么加一个小脚本算星期。前者更符合轻档，先试前者。
