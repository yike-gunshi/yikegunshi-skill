> 阶段：S2 设计 · 状态：已过完备性门禁（演示中由 AI 代确认）
> 读者：提需求的项目负责人确认边界；评测时对照考点
> 档位：轻档（交付一个 SKILL.md）；评测按完整档补做基线对照，理由见 0.2
> 日期：2026-10-22
> 这是写 SKILL.md 之前的设计。评测后迭代过一轮（删掉了执行流程第 5 步"回扫"，加了一条结论范围的规则），改动见 `迭代记录.md`。

## 0. Skill 化决策（S0 结论）

### 0.1 为什么做成独立 Skill

这件活满足三条资格：**会被重复使用**（每周几次会，每次会后都要整理）；**容易被路由错**（同样吃转写稿的还有播客笔记、课程导图、用户访谈提炼，"整理一下这个转写稿"这句话谁都能接）；**需要跨会话统一**（群里的人每次看到同一种结构，"什么算定了""负责人没说清怎么写"的判定口径每次一样）。

考虑过的替代方案和代价：

| 替代方案 | 代价 |
|---|---|
| 每次手贴一段 prompt | 能用，但判定口径要靠每次贴全；忘了贴就退回模型默认写法，而默认写法恰恰容易把"倾向"写成"结论" |
| 扩展已有的 podcast-summary | 它产出学习笔记（骨架图、问答、个人思考），立场是"帮自己学"；纪要的立场是"告诉别人要做什么"。硬塞进去两边都变胖，还会互相抢活 |
| 加一个 tool | 不缺能力。转写稿已经是文本，不需要查数或调接口 |
| 写进 CLAUDE.md | 这是一套操作流程，不是背景知识；写进去会在所有会话常驻，白占上下文 |

满足的资格条件：☑ 会重复使用 ☑ 容易被路由错 ☐ 有脚本能省重复劳动 ☑ 需要治理

### 0.2 分档

按 Skill 的分档表：就提需求的人自己用、不编排任何工具、路由错了代价低（没触发时手动说一句就行）——**轻档**，交付一个 SKILL.md，不建 references/ 和 scripts/。

但这件活"写错"的代价不低：错的结论发到群里会被当成依据执行，漏掉的待办没人做。要回答"用它和不用它差多少"，评测按完整档补做基线对照和考点评测。Skill 允许"缺什么再升，升档只加 references/scripts/evals，SKILL.md 本体不许跟着变大"，这里只升了评测。

## 1. 收料结论（S1）

访谈分三轮，每轮不超过三个问题。"回答"一栏里，来自场景设定的照录；场景设定没覆盖的，标【演示时由 AI 按默认确认】。

### 第一轮 · 需求与场景

| # | 问题 | 回答 |
|---|---|---|
| 1 | 这件事你多久做一次？转写稿从哪来？ | 我是项目负责人，每周开几次会，用飞书妙记或类似工具拿到转写稿。 |
| 2 | 纪要最后给谁看？他们打开第一眼要看到什么？ | 发到群里给参会人看，要一眼看到结论和待办。 |
| 3 | 什么算整理错了？哪种错你最怕？ | 最怕把没定的事写成定了；还有漏掉待办。 |

### 第二轮 · 输入与约束

| # | 问题 | 回答 |
|---|---|---|
| 4 | 转写稿一般长什么样？ | 口语化，有人名，有跑题，有很多"嗯""啊"。 |
| 5 | 会上没说清谁负责、什么时候做完，纪要里怎么写？ | 待办必须有负责人，没说清负责人的要标出来，不要猜。截止时间【演示时由 AI 按默认确认】：照原话写；会议日期已知时，"周五""下周一"这类说法在括号里补算出日期；"尽快""回头"写"未说定"，不替人定日期。 |
| 6 | 要不要自动发群、建任务、进日历？输出什么格式？ | 不接任何外部系统，输出 Markdown 就行。 |

### 第三轮 · 边界、失败与档位

| # | 问题 | 回答 |
|---|---|---|
| 7 | 有没有长得很像、但不该交给它的活？ | 【演示时由 AI 按默认确认】播客、课程、用户访谈的转写稿，多份纪要汇总成周报，会前写议程，拿纪要写跟进邮件，只把逐字稿洗干净——都不归它。它只管"一场会的转写稿 → 一份纪要"。 |
| 8 | 转写稿质量差时怎么办？比如只有"说话人1、说话人2"，人名前后识别得不一样，稿子中途断了。 | 【演示时由 AI 按默认确认】说话人只有编号时照写编号，不替人对上真名；同一个人名出现两种写法时照抄，列进"会后需确认"；稿子不完整就在纪要开头注明，已有部分照常整理。 |
| 9 | 这个 Skill 大概多少人用？用错了有什么后果？ | 就我自己用，每周几次。用错的后果是群里的人照着错的结论干活，漏掉的待办没人做。（据此定档，见 0.2） |

### 1.1 需求与场景

- **使用者与处境**：项目负责人，刚开完会，手里有一份几千到上万字的口语转写稿，要在会后尽快发纪要到群里。
- **现在怎么解决、哪一步最烦**：自己从头读一遍转写稿，边读边挑结论和待办。最烦的是分辨"这事到底定没定"，和从跑题、闲聊里把顺口派下的活捞出来。
- **理想产出**：一份能直接贴进群的 Markdown，最上面是结论和待办，每条待办有人、有时间；没谈拢的事单独列，不混进结论。
- **什么算做对了**：没拍板的事一条都不出现在"结论"里；会上派出的活一条不漏；负责人只写会上点名或自己认领的人。

### 1.2 已有决策与约束

| 类别 | 内容 | 可否推翻 |
|---|---|---|
| 平台与形态 | 输出 Markdown，贴进群聊或文档；不接外部系统 | 否 |
| 上下游 | 上游是飞书妙记或类似工具导出的转写稿（文件或粘贴）；下游是群里的参会人 | 否 |
| 合规与安全 | 不写转写稿里没有的内容；不替人认领待办 | 否 |

参考对象：

| 参考 | 借鉴什么 | 明确不借鉴什么 |
|---|---|---|
| 同仓库的 podcast-summary（同样从转写稿出发） | 先读完整转写再动笔，不跳读 | 骨架图、问答、个人思考段、飞书画板——那是给自己学习用的，群里的人不需要 |
| 常见的公文式会议纪要模板（会议信息 / 议题 / 讨论过程 / 结论 / 待办） | 待办三要素：事项、负责人、截止 | "讨论过程"段：群里没人读，而且最容易把讨论里的倾向写成定论 |
| 按时间顺序逐段摘要的纪要写法 | 无 | 整体不借鉴：读者要的是"定了什么、我要做什么"，不是会议重播 |

### 1.3 基建盘点

不适用：这个 Skill 不调用任何工具，输入就是一份文本。

## 2. 设计

### 2.1 要解决的问题

替项目负责人把一场会的口语转写稿，变成一份能直接发群的纪要：定了什么、谁在什么时候之前做什么、还有什么没谈拢。

### 2.2 定位与边界

**定位**：一份发到项目群里的会议纪要。像一个靠谱的项目助理——只记"定了什么、谁去做、还卡在哪"，把"这场会到底定了什么"讲透，不复述讨论过程。

**核心立场**：群里的人拿纪要当执行依据，所以两种错的代价不一样，两个模块要朝相反的方向偏：

- **结论宁缺**：拿不准算不算定了，就放进"没谈拢"。错写一条结论，会有人照着去做；漏写一条，最多有人在群里问一句。
- **待办宁全**：只要有人认领或被点名去做一件事，哪怕是跑题时、散会前顺口一句，也要捞出来。负责人说不清就标出来，而不是丢掉或替人认领。

**范围**：给定一场会议的转写稿（文件或粘贴的文本），产出一份纪要。一次只处理一场会。

**不处理**：

| 不处理什么 | 交给谁 |
|---|---|
| 播客、讲座的转写稿整理成学习笔记 | podcast-summary |
| 课程、长文转成思维导图 | book-to-mindmap |
| 用户访谈转写稿提炼痛点和洞察 | 直接做（这是用户研究，要的是洞察，不是待办） |
| 把多份纪要汇总成周报 | 直接做 |
| 会前写议程、根据纪要写跟进邮件 | 直接做 |
| 只把逐字稿洗干净、一句不删 | 直接做 |
| 想把会议纪要这件事做成 Skill | skill-build |

**≥3 个"很像但不该触发"的 query**（门禁第 1 条）：

1. 我昨天听了一期商业播客，转写稿在 transcripts/播客-E88.txt，帮我整理成学习笔记
2. 这是三场用户访谈的录音转写，帮我提炼一下用户痛点和需求
3. 把这份转写稿的嗯啊口头禅去掉，整理成通顺的逐字稿，内容一句别删
4. 把这周的几份会议纪要汇总成一份周报发给老板
5. 帮我写个 skill，把会议转写整理成纪要

### 2.3 触发与意图路由

**触发层素材**

- 应触发：开完会让整理纪要；只说"帮我看看会上定了啥、谁要干啥"；直接粘贴一段"说话人1 00:03:12 嗯那个……"让出纪要；英文混说"整个 minutes，action items 带 owner"；把一场复盘会、站会、供应商沟通会的转写稿交过来。
- near-miss 负例：见 2.2 的 5 条，再加"会议纪要一般怎么写""帮我拟下周会的议程""这节课的录音转文字做成导图"。
- 可能抢活的隔壁 Skill：podcast-summary（同样吃转写稿）、book-to-mindmap（"整理成结构"）、skill-build（"做成 skill"）。

**路由层分流**

| 意图强度 | 判断信号 | 应答粒度 |
|---|---|---|
| 强 | 给了转写稿（文件路径或粘贴的文本），并要纪要、要结论待办、要"会上定了啥" | 完整纪要，走全流程 |
| 弱 | 说要写纪要，但没给转写稿 | 一句话说明会出什么结构，请他把转写稿发来 |
| 潜在 | 给了转写稿，但问的是一个具体问题（"张总对方案什么态度"） | 先回答那个问题，再问一句要不要出整份纪要 |

### 2.4 输出框架

**固定骨架**（顺序锁死，任何一场会都按此结构）

1. 标题行 + 会议信息（日期、参会人）
2. 结论
3. 待办
4. 没谈拢的问题
5. 会后需确认（命中才出）

**必出模块**

| 模块 | 入选条件 | 内部结构 | 对应考点 |
|---|---|---|---|
| 会议信息 | 总是出 | 日期（转写稿没写就注明"未标注"）、参会人（转写稿里出现的发言人） | K8 骨架 |
| 结论 | 会上有人拍板且当场没人反对，或者全场明确同意；会上改过口的以最后一次为准 | 每条一句话 + 谁拍的板。一条都没有时写"本次会议没有形成明确结论" | K1 不夸大、K2 结论召回 |
| 待办 | 有人认领，或被点名去做一件事 | 负责人在前：`负责人：事项（截止：…）`。负责人没说清写"负责人待定"并附原话；截止没说写"未说定" | K3 待办召回、K4 负责人、K5 截止 |
| 没谈拢的问题 | 讨论过但没收口的事，包括"倾向于""先这样吧回头再看" | 问题 + 各方意见或倾向 + 下一步（会上提了才写） | K6 未决召回 |

**触发式模块**

| 模块 | 触发条件 | 命中多个时怎么取舍 |
|---|---|---|
| 会后需确认 | 人名前后识别不一致、数字前后矛盾、说话人只有编号、稿子中途断了 | 全部列出，每条一行；没有就不出这个模块 |

> 门禁第 3 条：四个必出模块都对应到了考点（见考点表）；K7"无编造"对应全篇。
> 模块总数 5 个，未超过 8 个。

### 2.5 执行流程

| 步 | 做什么 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|---|
| 1 | 读完整转写稿，不跳读 | 文件或粘贴的文本 | 会议日期、参会人、大致议题 | 文件读不到：请他重新给路径或直接粘贴。稿子很长：分段读完再写，结论跨段合并 |
| 2 | 第一遍，标三类信号：拍板、认领或点名、分歧或搁置 | 全文 | 三张候选清单 | — |
| 3 | 判结论还是没谈拢：看收口信号；同一件事前后变过，以最后一次为准 | 拍板与分歧候选 | 结论 / 没谈拢 | 拿不准的放没谈拢，写出倾向 |
| 4 | 定待办三要素：负责人只写点名或自己认领的人，截止只写原话 | 认领候选 | 待办清单 | 负责人说不清：写"负责人待定"附原话；只有说话人编号：照写编号 |
| 5 | 回扫一遍：重点看跑题段和散会前几分钟，核对待办有没有漏 | 全文 + 待办清单 | 补齐后的待办 | — |
| 6 | 按固定骨架输出 | 以上 | 纪要 Markdown | 稿子不是会议（单人口述、播客）：说明一句，问他是否仍要按纪要整理 |

### 2.6 辅助资源

轻档，不建。判定规则和输出骨架都短，写在 SKILL.md 正文里就够；评测用的转写稿和标准答案放在 Skill 包外面，不进包。

### 2.7 输入输出定义

**预期输入**：会后的项目负责人，丢来一份转写稿文件路径，或直接粘贴大段转写文本，附一句口语要求。

**≥5 条真实的、带细节的 query 样本**（门禁第 5 条）：

1. 刚开完周会累死了，妙记导出来在 ~/Downloads/会员小程序周会_1019.txt，帮我整理成纪要发群里，待办别漏了
2. 今天跟市场那边的协调会，吵了半天发布日期，转写稿在附件。帮我理一下到底定了啥、谁要干啥，我要发群里
3. （粘贴一大段）说话人1 00:03:12 嗯那个就是这个工单超时的事……帮我出个会议纪要
4. 帮我看看这个 transcripts/双十一运营会.txt，马骁说的那几件事分别是谁负责、什么时候交
5. standup 的 transcript 在 ~/Desktop/standup-1021.txt，整个 minutes，action items 要有 owner
6. 下午供应商沟通会的记录，老板要我半小时内发群里，结论、待办、没定的分开写

**预期输出**：一份 Markdown 纪要，结构见 2.4，长度跟着会议内容走，不设字数上限；结论和待办在最前面。

### 2.8 上下文分层规划

| 层 | 放什么 | 预估体量 |
|---|---|---|
| description | 做什么 + 同义触发说法 + 排除项 | 约 300 字 |
| SKILL.md 正文 | 定位与立场、意图分流、六步流程、判定规则、输出骨架、红线、失败处理 | 目标 150 行以内 |
| references/ | 不建 | — |
| scripts/ | 不建 | — |
| assets/ | 不建（骨架写在正文里） | — |
